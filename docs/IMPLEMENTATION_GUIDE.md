## 0. 如何使用本文档（代理必读）

### 0.1 阅读顺序

1. **§1 愿景与范围**、**§2 硬约束**、**§3.7 动机设计宪章**：每次开工前都要对照。任何会影响玩家动机的功能（奖励、提示、推送、进度、社交、角色台词）都必须逐条对照 §3.7。§2 的规则优先级高于本文档其他任何部分，也高于你自己的“更好的想法”。
2. **§12 里程碑**：找到当前所处的里程碑，只做该里程碑及以前的任务。
3. 按任务需要查阅 §4–§11 的详细设计。
4. **§13 工程规范**：提交代码前对照。
5. **§14 待决问题**：遇到这些问题时**停下来问人类**，不要自行决定。

### 0.2 代理工作规则

- **不跨里程碑**：不要提前实现后续里程碑的功能，但可以为它们留扩展点（trait、枚举分支、schema 中的可选字段）。
- **违背 §2 的需求要上报**：如果某个任务看起来必须违反 §2 才能完成，写一份 ADR 草案（`docs/adr/NNNN-*.md`），停下来等人类决定。
- **不编造科学内容**：不确定的物理常数、参数范围、文献出处，标为 `TODO(expert)` 或 `source: unsourced`。**严禁编造文献引用**。未注明来源的参数在发布验收（V3）时必须失败。
- **小步提交**：每个 PR 只做一件事，附上测试，并在描述里列出它满足了哪条退出标准。
- **机器可读输出优先**：所有 CLI 命令支持 `--json`；错误使用 §5.4 的诊断码。这样其他代理才能自动修复。
- **文档与代码同步**：改了 schema 或公共 API，必须同步改本文档和 `docs/` 下的对应页面。

## 1. 愿景与范围

### 1.1 一句话

一个网页上的、由“可运行的科学模型”构成的持久小世界。玩家通过**有引导的探究**亲手重建科学知识，学到的东西会变成世界里真实运转的设施；所有玩家的“研究请求”共同把这个世界越扩越大。

**初心：逆练应用心理学。** 许多以“骗氪”为核心的页游、手游、小程序游戏，以及一部分二次元游戏，本质上是应用心理学的集大成，但它们把这些机制用在了让人花更多钱、花更多时间上（“邪修”）。本项目要“逆练”：用同样深的心理学功力，服务于让人真正学会，并且离开游戏后生活更好（“正修”）。这决定了两件事：
- 产品的入门体验要对标的是这些游戏，而不是教育软件；
- 所有动机设计都必须通过 §3.7 的动机设计宪章（P15）。

### 1.2 长期目标

- 覆盖绝大部分非实践类的理工科与计算社会科学：力学、电学、热学、场论、化学动力学、生态、流行病、经济、语言演化、教育学，以及数学推导、算法与离散结构。
- 内容可以由 LLM 管线辅助生成，但必须经过分层验收；面向“实证”知识的内容必须经过人类专家审核。
- 非营利导向，目标是惠及尽可能多的人。盈利若有，只是顺带。

### 1.3 当前阶段的约束

| 约束 | 含义 |
|---|---|
| 一人开发 | 早期只有一名开发者（借助 AI 代理）。设计必须优先考虑**单人可维护**，避免分布式系统、微服务、复杂运维。 |
| 专家后续加入 | 多位理工科专家愿意在底座完成后贡献内容。所以 **M5 的作者底座**（专家不依赖开发者就能写模块）是关键的交付节点。 |
| 网页优先，移动端优先 | 先只做网页版，**不做小程序、不做原生 App**。L0–L1 层的体验（§3.6）、世界视图和科技网络视图按**手机浏览器优先**设计：触屏操作、中端安卓机的性能预算、可以安装成 PWA。L2–L3 层的公式编辑和代码编辑以桌面为主，手机上可用即可。 |
| 盈利与资质暂不处理 | 暂不实现支付、皮肤商城。但架构上要允许以后加入（例如角色外观是数据驱动的）。 |
| 受众：低地板、高天花板 | 入门门槛对标大众手游：任何会玩手游的人都能从 L0 开始（§3.6）。首批内容的**天花板**是大学水平：L2–L3 可以直接使用微积分、线性代数和 Python。受众下沉意味着一定会有未成年人，所以默认按“可能有未成年人”来设计：无公开聊天、最少数据收集、无支付。 |

### 1.4 非目标（当前不做）

- 实时 LLM 生成（运行时让 LLM 生成内容或驱动 NPC）。LLM 只出现在离线的内容生产管线中。
- 高精度工程仿真（CFD、FEM 级结构分析）。精度目标是“定性正确、数量级正确、关键关系定量正确”。
- 3D 写实画面。画面以 2D 俯视角 / 2.5D 风格化为主。
- 多人同屏实时联机。社交是异步的（分享蓝图、共享知识图谱）。

## 2. 硬约束（设计原则）

以下规则编号为 P1–P12，代码评审和 ADR 中直接引用编号。

- **P1 模型即数据**：每个具体模型（电厂、传染病、市场）都是一份声明式文件（YAML），引擎只是解释器。LLM 和专家都只产出数据文件，**永远不在运行时生成或注入内核代码**。两个例外都受严格限制：（1）学习者自己写的 Python 代码（§5.7.5），只能通过数据集和宏步边界的策略调用与内核交互（K10）；（2）可选的作者侧 Rhai 逃生口（§5.7.2），使用它的模块会被标记为“可验证性降低”，并强制要求专家审核。
- **P2 确定性**：给定相同的模型文件、种子和玩家操作序列，仿真结果在所有平台（native x86_64 / aarch64 / wasm32）上**逐位一致**。具体规则见 §5.12，由 CI 强制检查。
- **P3 内核分层**：仿真内核 crate 不依赖任何渲染、UI、网络、教学逻辑。教学（课程、提示、评分）是内核之上的一层；世界（存档、端口分配、全局修正）也是内核之上的一层。
- **P4 一份内核，两个目标**：同一份 Rust 代码同时编译为 WASM（玩家端）和 native（CLI、验收、批跑）。**验收所用的内核和玩家运行的内核必须是同一份代码**。
- **P5 每个数都有单位**：所有变量、参数、端口都声明单位，编译期做量纲检查。无量纲量显式写 `"1"`。
- **P6 每个参数都有出处**：非玩家可调的参数必须引用参数库条目或文献；数值必须落在引用给出的范围内。
- **P7 先有尺子，再放开生产**：验收体系（§8）的建设优先于内容生成管线（§11）。没有通过相应级别验收的内容不得发布。
- **P8 黑盒换白盒**：世界永远有“默认供应”（飞船预留设备、原住民的传统技艺）。学习的意义是**把黑盒换成自己理解的白盒，并改进它**，而不是从 0 到 1 的解锁许可。不存在因为没学某门课就整个卡死的状态。
- **P9 有界改进**：玩家能把组件改进多少，受“包络”约束（§7.6）。每次学习的收益可以感知，但有上界，以防数值膨胀。
- **P10 实证与思辨分区**：现实科学（实证区）和假想学科（“假想实验室”）在数据、UI、验收流程上严格分区。假想实验室的每个结论都必须展示它依赖的假设（§8.8）。
- **P11 不学不能成为最优解**：任何机制（社交分享、原住民天才、氪金、挂机）都不能让玩家绕过掌握度检查而获得同等收益。原住民路线（§7.13）不违反本条：它需要玩家学习另一组节点，并且明显更慢。
- **P12 国际化从第一天开始**：所有面向玩家的文本走 i18n 键。首批语言为 `zh-CN` 和 `en`。
- **P13 范式可插拔，核心抽象先定**：新增一种仿真范式，只能新增 crate（以及可选的前端视图组件），**不得修改** §5.6.3 中 K1–K14 定义的核心抽象（值类型、时间模型、分析层、数据集、连接器语义、事件排序键等）。如果确实需要修改，先写 ADR 并获得人类批准。所以这些抽象在 M1 就要按完整形态**设计好接口**，即使大部分要到后面才实现。
- **P14 素材必须有授权记录**：任何美术、音频、字体素材，入库时必须在 `assets/LICENSES.yaml` 中记录作者、来源和许可证。没有记录的素材，CI 拒绝合并。
- **P15 动机设计宪章**：所有动机机制都必须通过两项测试（§3.7）。（1）**透明测试**：把这个机制如何作用于玩家完整地讲给玩家听，它依然有效，玩家依然认可。（2）**生活测试**：它让玩家离开游戏后的生活更好，而不只是让玩家更难离开。§3.7 列出的红线机制，在任何情况下都不实现。
- **P16 不卡住按需学习的人**：明确知道自己想学什么的人，不能被设计卡住：搜索可以穿透迷雾，全图模式随时可用；在更合适的时候，主动推荐外部的单领域资源（§6.6、§9.6）。

## 3. 产品与玩法概览（实现所需的上下文）

### 3.1 叙事

- 一艘飞船发现了宜居星球，降落时出了故障：通信损坏，能源不足以返航。
- 飞船执行预案：由**鲸鱼娘机器人**负责探索星球、获取资源、修复通信和飞船。
- 飞船预留的资源（太阳能板、滤水器等）足以维持飞船自身消耗，并给鲸鱼娘补给。这就是“默认供应”（P8）。
- 由于数据损坏或参数丢失，鲸鱼娘需要**从头推导**很多知识。这是学习的叙事理由，也和“玩家补全模型”的玩法同构。
- 鲸鱼娘不需要进食，但吃到食物（尤其是**白饭**）会获得增益。食物把农业、化工、能源串成一条产业链的终端。
- 科技树发展到一定程度后，可以建造**子代理**（小鲸鱼娘机器人）。
- 星球上有处于语言发展初级阶段的智慧族群（下文称“原住民”）。鲸鱼娘与他们是**合作、互惠**的关系：学习语言学、心理学、教育学能促进沟通与共同发展。原住民的可靠性不如子代理，但数量呈指数增长（受承载力约束），并会涌现天才（§7.13）。
- **第一次相遇**（Q21）：鲸鱼娘降落后架设好太阳能板、滤水器等维持飞船消耗的设备，**第二天**就遇到原住民。
- **原住民体型小、寿命短、代际快**（代际约 3–5 个原住民年，工作假设）。这是平方-立方定律和代谢标度律的推论，也是“新一代来请教”（§6.8）和原住民文明肉眼可见地变化（§7.12）的设定基础。
- **原住民有自己的科技发展**（§7.13）：他们在同一张科技网络上独立推进，玩家可以引导、支持，但不替他们一蹴而就。叙事上，鲸鱼娘选择让原住民以更自然的节奏发展科技和社会；准确地说，这是引导，而不是放任。
- **教子代理与教原住民是核心玩法之一**（§6.8）：学会的东西，要能交给子代理执行、讲给原住民听。讲给别人听本身就是最强的复习方式，所以复习在叙事上表现为“新长大的一代原住民来请教”和“子代理遇到了新情况”。
- **原住民外形**：Q 版风格，不一定是人形。外形必须符合星球环境（重力、大气、昼夜长度、气候）和演化逻辑。这本身就可以做成一组课程（例如平方-立方定律、Kleiber 代谢定律、视觉与光谱的关系），让玩家自己推导出“他们为什么长这样”。具体设计待定。
- 基础学科（数学、物理）提供全局修正：子代理与原住民的数量上限、协同效率等。
- **阶段目标**：
  - 第一阶段：修复通信和能源系统，并造出能独立驾驶飞船的子代理。结局是**子代理驾驶飞船返航，鲸鱼娘选择留下**。所以“建造子代理”是第一阶段主线的硬性要求，而鲸鱼娘留下的情感理由（与原住民的羁绊）要在第一阶段中期开始铺垫。教原住民的过程（§6.8）是铺垫这份羁绊的主要载体。
  - **原住民路线**（§7.13）：返航所需的能力中，推进剂、推力、制导等可以由原住民自己发展出来，但**驾驶员必须是玩家自己造的子代理**（原住民寿命太短，无法完成远距离的星际航行）。玩家亲自学得越少，就要等原住民发展越久：最少投入时约需两千个原住民年，在实践中等不到（P11）。
  - 第二阶段：与母星的星际通信，以及与原住民共同的长期发展（例如戴森球）。

### 3.2 核心学习循环（有引导的探究）

```
观察现象 ─▶ 提出问题 ─▶ 用仪器测量 ─▶ 建模（补全模型中的“洞”）
     ▲                                          │
     │                                          ▼
请教与运维（间隔复习） ◀─ 部署 / 教给子代理与原住民 ◀─ 对照修正 ◀─ 预测
```

- “观察现象”有两个入口：课程中的实验现象，以及原住民小故事里的现象和原住民的猜想（§7.14）。
- 每节课背后有一个**真模型**（truth，由专家或经审核的管线产出），对玩家隐藏，用来生成“星球实测数据”。
- 玩家拿到的是**带洞的模型**：缺一个方程、一个参数，或一条因果连接。玩家用仪器采集数据，补全模型，再做预测并与观测对照。
- 通过检查后，模型（白盒）可以部署进世界，替换或改进对应的黑盒设施。
- 学会的东西还可以**教出去**（§6.8）：交给子代理执行（要求精确，对应 L2–L3），或讲给原住民听（要求说服：设计一个能让对方亲眼看到自己错了的判别实验，对应 L0–L1）。
- 之后世界会周期性地出现**请教事件**（新一代原住民带着误解来请教）和**运维事件**（负荷波动、部件老化、粉尘覆盖、子代理遇到新情况），本质上都是间隔复习：玩家需要回来讲解、诊断、调参。

### 3.3 共享世界与研究请求

- 玩家可以通过“向飞船计算机提交研究请求”，请求学习某个主题。
- 请求会被归一化，映射到**共享知识图谱**上的节点：已有节点就加票；没有的节点进入生成队列。生成、验收、审核之后，节点**对所有玩家发布**。
- 知识图谱的增长就是星球“已知世界”的增长：新地貌、新资源、新原住民文化、新设施类型。
- 每个玩家的存档是自己的世界实例，但内容目录是共享的。
- 内容结构是一张**科技网络**：一般的有向网络，而不是树（§9.3–§9.6）。
- 阶段目标按**能力需求**定义，而不是按节点列表定义（§7.11）。最小必须路径由程序计算，主线只用 L0–L1 就能走完；不在最小路径上的节点，提供效率、余量、替代路线、原住民线与情感线，以及后续阶段的基础。
- **迷雾**：飞船数据库的索引损坏了，学会一样东西，就修复一片索引。玩家看得到已点亮的节点、前沿节点和按相关度筛选的轮廓节点；当前目标始终可见（§9.6）。
- **全图模式与搜索**：明确知道自己想学什么的玩家，可以随时打开全图，或直接搜索，看到通往目标的路径（P16）。

### 3.4 社交（异步）

- 好友之间可以分享自己科技树上与对方**距离为 1** 的节点的**蓝图**。
- 蓝图给的是**入口和加速**（课程提前解锁、时间加成、额外提示），**不给掌握度**（P11）。

### 3.5 平行星球与假想实验室

- **平行星球**：把存档分叉成 N 个副本，各自注入不同的参数或制度，快进之后并排比较。叙事上是“飞船计算机的推演沙盒”。
- **假想实验室**：思辨性的学科构造（基于热力学与博弈论的法学、能量货币、教育生产函数等），与实证科技树分开，并强制展示假设清单与敏感性分析（§8.8）。

### 3.6 表示层：低地板、高天花板、宽墙壁

同一个真模型，提供四个表示层。玩家可以停留在任何一层，也可以随时深入。

| 层 | 玩家做什么 | 检查方式 | 需要的前置知识 |
|---|---|---|---|
| L0 直觉层 | 直接操作世界里的对象，观察后果 | 世界状态是否达标（`world_state`） | 无 |
| L1 因果层 | 画因果箭头，只标“增加 / 减少” | 因果方向是否正确（`causal_sign`，复用弹性和单调性测试） | 无 |
| L2 定量层 | 写带单位的公式、估计参数 | `expr_equiv`、`param_within`、`trajectory_fit` 等 | 初中到高中数学 |
| L3 推导 / 代码层 | 推导，或用 Python 写策略、算法 | `derivation`、`property` | 大学 |

规则：
- 每节课至少提供 L0 和 L1；大多数课程提供 L2；L3 可选。
- 主线（§7.11）必须能只用 L0–L1 走完；更深的层带来效率和余量。
- 掌握度按层记录：同一个节点可以是“L1 已掌握，L2 未学”。
- 表示层只存在于课程层和前端，内核不因此改变（P13）。
- 教原住民（判别实验）在 L0–L1 即可完成；教子代理按玩家已掌握的最高层进行（§6.8）。

### 3.7 动机设计宪章（P15 的展开）

**两项测试**：透明测试与生活测试（见 P15）。设计评审时，每个影响动机的功能都要写明它如何通过这两项测试。

**邪修 → 正修 对照**

| 邪修机制 | 它利用的心理 | 正修版本 |
|---|---|---|
| 体力 / 能量系统 | 人为制造稀缺，逼你付费或按时回来 | 学习永远不被限制；“今天学够了”是一个明确的、被庆祝的停止点。原住民时钟有每周时间额度（§7.12），用完后只是村子“入夜”，课程、设施、编年史照常可用；额度可以累积，所以不规律的玩家不吃亏；离线时世界是否流逝由玩家选择 |
| 连续签到，断了清零 | 损失厌恶、沉没成本 | 只记累计，不记连续，中断没有惩罚。回来的理由是真实的需要（设施要维护、新一代原住民来请教，也就是间隔复习），而不是怕失去 |
| 抽卡 | 可变比率强化 | 惊喜来自世界本身的涌现（原住民天才、模拟中意想不到的结果）；随机永远与金钱无关，概率公开。原住民突破“何时发生”是确定的（可见的研究进度），只有“突破什么”是随机的（§7.13）；小故事没有稀有度（§7.14） |
| 限时活动、限定角色 | 错失恐惧 | 没有永久错过的内容；活动可以周期性重来；社区研究请求只设目标，不设期限 |
| 公会义务、社交施压 | 归属需要、互惠压力 | 异步合作，没有义务；分享蓝图对双方都有好处；不设按在线时长排名的榜单 |
| 角色养成、“老婆”依恋 | 准社会关系 | 鲸鱼娘关心你在现实中过得怎么样，为你真正理解了什么而高兴；**绝不**使用“鲸鱼娘想你了”这类让人愧疚的推送 |
| “你不在，他们就忘了” | 愧疚感、损失厌恶 | 请教来自**代际更替**（新长大的孩子、别的村子听说了来问），不是因为玩家缺席而让人遗忘；原住民之间会互相传授，知识不会因为玩家离开而消失（§6.8） |
| 图鉴收集、完成度 | 对未完成之事的惦记（蔡格尼克效应） | 科技网络与星球图鉴：收集的是理解，每一格都要靠掌握度点亮 |
| 数值膨胀的爽感 | 能力感 | 世界肉眼可见地变好，但改进有上界（P9），靠的是理解 |
| 难度卡点，卖通关道具 | 把挫败感转化为付费 | 难度平滑：卡住时自动提供下一级提示，或换一个表示层 |
| 多层货币、首充、VIP | 价格模糊、锚定效应 | 将来如果卖皮肤：直接标价，只卖外观，没有随机付费内容，设消费上限 |
| 新手期高密度奖励 | 即时反馈、早期胜利 | **直接学习**：这是那些游戏真正做得好的地方 |

**红线**（任何理由都不实现）：付费随机内容；限时独占内容（永久错过）；进度丢失，或以丢失进度相威胁；愧疚式推送；限时购买压力；强制社交义务；确认羞辱式界面（例如“不了，我不想变强”）；以在线时长或日活为优化目标的 A/B 测试；把遗忘归咎于玩家缺席的叙事（例如“因为你好久没来，村民们都忘了”）；有期限或拒绝有惩罚的请教；用时间额度阻止学习；不可累积的每日额度（等于变相签到）；以“上线领取”为形式的离线收益界面；带稀有度标记的故事或突破。

**奖励的形式**：奖励“理解的那一刻”（模型和数据对上的瞬间，以及原住民亲眼看到实验结果、想通了的瞬间），使用信息性反馈（“你的模型现在能解释夜间掉电了”），避免控制性的外在奖励（“完成任务得 50 金币”）。后者会削弱内在动机，即“过度理由效应”。

**新手体验**：60 秒内第一次成功；5 分钟内第一次改变世界；不出现大段文字；第一次见到公式之前，至少已经在 L0 和 L1 各成功过一次。

**停止点**：每次会话都有自然的停止点和会话摘要；不设计“再来一把”式的强迫循环。

**鲸鱼娘的行为准则**：关心玩家在现实中的状态（深夜会劝玩家休息）；为真实的理解而高兴；不使用愧疚感，不制造焦虑，不夸大损失。

**拆解模式**：心理学方向有一门课，以游戏自己的机制为标本，讲解每个机制为什么存在、如何作用于玩家、正修与邪修的区别在哪里。学完的玩家能识别其他产品里的骗氪设计。这门课必须包括请教事件：直接说明“来请教的人，是复习调度为你安排的”，以及为什么讲给别人听是最好的复习（§6.8.6）。

**指标**（§11.1）：只优化学习增益、回顾性认可和健康度，不以在线时长、日活为目标。

**将来若有收入**：只卖外观，直接标价，没有随机付费内容，设消费上限，不卖时间加速。

### 4.2 数据流

1. 内容仓库（YAML）经 `cetus bundle` 构建成带内容哈希的版本化内容包，部署到静态 CDN。
2. 前端按需下载内容包，交给 Worker 中的 WASM 内核编译、运行。
3. 存档：M4 起存在本地 IndexedDB 并支持导出文件；M10 起支持云同步。
4. 验收：CI 中用 native 内核跑 `cetus verify`；同时用 WASM 内核（Node 或 wasmtime 执行）跑确定性对比。

### 4.4 技术选型总表

版本号在 M0 时取当时的最新稳定版，记录在 ADR-0001 中并锁定。下表只列选择和理由。

| 领域 | 选择 | 理由 / 注意 |
|---|---|---|
| 内核语言 | Rust（stable，edition 2024） | WASM + native 双目标；无 GC；serde 生态 |
| WASM 构建 | `cargo build --target wasm32-unknown-unknown` + `wasm-bindgen` CLI + `wasm-opt`（binaryen） | **不用 wasm-pack**：它已随 rustwasm 组织于 2025 年归档。wasm-bindgen 已迁到新组织继续维护。CLI 版本必须与 crate 版本一致。 |
| 序列化 | `serde`；YAML 解析用一个**仍在维护**的 crate（候选：`serde_yaml_ng`、`serde-saphyr`，M0 中写 ADR 确定） | **不要用 `serde_yaml`**（已归档）。快照用 `postcard`（二进制），调试导出用 JSON。 |
| JSON Schema | `schemars` | 从 Rust 类型生成 schema，给编辑器补全和 LLM 结构化输出用 |
| 诊断输出 | `miette` 或 `ariadne` | 带源码定位、人类和机器都读得懂的错误 |
| 线性代数 | `nalgebra` | 稠密 LU（隐式 ODE 的雅可比），刚体库也依赖它 |
| 图 | `petgraph` | 网络空间、知识图谱检查、依赖排序 |
| 随机数 | `rand` + `rand_chacha` | 可复现、可分流 |
| 数学函数 | `libm` | 纯 Rust 实现，保证跨平台一致（§5.12） |
| 有序容器 | `indexmap`、`BTreeMap` | 遍历顺序确定 |
| 哈希 | `blake3` | 状态哈希、内容哈希 |
| 压缩 | `lz4_flex` 或 `miniz_oxide` | 纯 Rust，可编译到 WASM |
| 刚体 | `rapier2d`，开启 `enhanced-determinism` | 官方保证跨平台确定性（含 WASM）；不能与 `simd8` 同时开启；初始值里的三角函数要用 nalgebra 的 `RealField` 方法 |
| 学习者编程语言 | Python（Pyodide，在专用 Worker 中按需懒加载） | 算法课、数据分析课、玩家自写控制器或策略、后续的 CAS（SymPy）都用它。确定性与安全要求见 §5.7.5 |
| 作者脚本逃生口（可选） | `rhai` | 只在 ABM 规则的作者侧逃生口中考虑，M6 时用 ADR 决定是否需要。**学习者永远写 Python，不写 Rhai。** |
| 属性测试 | `proptest` | 单位系统、表达式、快照往返 |
| 前端构建 | Vite + TypeScript（strict） | |
| UI 框架 | React | 生态最大（xyflow、MathLive 封装等） |
| 模型画布 | `@xyflow/react`（React Flow） | 存量-流量图、agent 规则图、端口连线 |
| 世界与场渲染 | PixiJS（v8） | 2D 俯视角，WebGPU 优先、WebGL 降级 |
| 时序图 | uPlot | 高性能时间序列；复杂图表可补 ECharts |
| 公式输入 | MathLive（+ Compute Engine 转 MathJSON） | 玩家可视化输入公式；同时支持 ASCII 输入 |
| 代码编辑 | CodeMirror 6 | YAML 编辑（作者预览）、Python 编辑（算法课、数据课） |
| 图谱布局 | elkjs（分层 DAG）或 Cytoscape.js | 知识图谱视图 |
| Worker 通信 | Comlink | |
| 前端状态 | Zustand | |
| 本地存储 | Dexie（IndexedDB） | 所有读写都包 try/catch，失败时降级为内存模式并提示导出 |

## 5. 仿真内核详细设计

### 5.1 量纲与单位（`cetus-units`）

**表示方式**
- 量纲是一个有理指数向量：7 个 SI 基本量纲（L 长度、M 质量、T 时间、I 电流、Θ 温度、N 物质的量、J 发光强度），再加上**可扩展的自定义基本量纲**（例如 `person` 人口、`currency` 货币、`bit` 信息、`item` 物品计数）。自定义量纲在内容仓库 `content/units/dimensions.yaml` 中登记。
- 指数用小分数（`i8/i8`）表示，以支持 `m^(1/2)` 这类情况。
- 单位 = 量纲 + 到 SI 的换算因子（仿射单位，如 °C，只允许出现在输入输出端，内部一律用 K）。
- 内部计算全部用 SI 基本单位的 `f64`。单位只在编译期检查，并在边界处做换算。

**单位表达式语法**：`kW*h`、`W/m^2`、`kg*m/s^2`、`1/s`、`mol/(L*s)`、`"1"`（无量纲）。支持 SI 前缀，并内置常用单位表（h、day、year、L、bar、eV、cal、°C、%……）。**星球的“日”（day_local）**是一个以星球日长定义的单位，由世界层注入。

**规则**
- 加减、比较：两边量纲必须相同。
- 乘除：量纲指数相加减。
- `exp`、`ln`、`sin` 等超越函数：参数必须无量纲；`sin`/`cos` 接受 `rad` 或无量纲。
- `sqrt`、`pow(x, r)`：r 必须是编译期常量有理数。
- 字面量 `0` 是**量纲多态**的，可以与任何量纲比较或相加；其他字面量默认无量纲，需要单位时写成 `1000[W/m^2]`。

**扩展单位（K14）**
- 对数单位（dB、pH、Np、星等）只作为输入和显示时的变换，内部一律使用线性量。
- 角度：`rad` 在量纲上是无量纲的，但带一个 `angle` 标签。把角度和非角度的无量纲量相加时给出警告 W1301。
- 计数（`item`、`person`）、货币（`currency`）、信息（`bit`）都是自定义基本量纲，不允许与无量纲量隐式混用。

**尺度（K13）**：变量可以声明 `scale:`（典型量级，例如 `scale: "1e-10[m]"`）。求解器的绝对容差按 `scale` 推导，这样从量子尺度到天文尺度的模型都不会因为容差设置失当而失真。未声明时，从 `initial` 和 `range` 推断。

**测试**：用 proptest 生成随机单位表达式，验证解析→打印→解析往返一致、换算因子一致、量纲代数满足交换律和结合律。

### 5.2 表达式语言（`cetus-expr`）

一门小而严格的表达式语言，供所有范式共用。

**语法要点**（EBNF 草案放在 `docs/schema/expr.ebnf`）
- 运算：`+ - * / ^`、比较 `< <= > >= == !=`、逻辑 `and or not`、条件 `if c then a else b`。
- 字面量：数字、带单位的数字 `3.2[m/s]`、布尔。
- 标识符：同一模型内的变量、参数、存量、流量、观测量；用 `component.var` 引用组件端口变量。
- 内置变量：`time`、`dt`（只读，并给出警告：公式依赖 dt 通常是建模错误）。
- 内置常量：`pi`、`e`，以及物理常数库中的常量（`c0`、`k_B`、`N_A`……带单位）。
- 内置函数：
  - 数学：`min max abs clamp exp ln log10 sqrt pow sin cos tan atan2 floor ceil round`
  - SD 专用：`step(height, t0)`、`pulse(...)`、`ramp(...)`、`delay1(x, tau)`、`delay3(x, tau)`、`smooth(x, tau)`、`lookup(table_id, x)`（图形函数，分段线性）
  - 随机（只在 ABM / 观测噪声中可用，必须绑定到某个随机子流）：`chance(p)`、`normal(mu, sigma)`、`uniform(a, b)`
  - 聚合（桥接用）：`count(Type where cond)`、`sum(Type.attr where cond)`、`mean(...)`
  - 场（PDE 用）：`lap(F)`、`grad(F)`、`div(V)`、`advect(F, V)`
  - 时间查询（只在测试 / 检查器中可用）：`first_time(cond)`、`value_at(x, t)`、`integral(x, t0, t1)`
- **值类型（K1）**：类型检查器从 M1 起就基于完整的 `Type` 枚举设计：

```rust
pub enum Type {
    Scalar(Dim), Int(Dim), Bool, Enum(EnumId),
    Complex(Dim),                         // 量子、波动光学、交流电路（M7 之后实现）
    Vector(Box<Type>, usize),             // 定长向量，元素同量纲
    Matrix(Box<Type>, usize, usize),      // 定长矩阵
    Array(Box<Type>),                     // 变长数组（agent 属性列等）
    Field(Box<Type>, GridId),             // 网格场
    Table(AgentTypeId), Graph(GraphId), Geometry(GeomKind), Dataset(DatasetSchemaId),
}
```

  M1 只实现 `Scalar`、`Int`、`Bool`、`Enum`；其余分支在编译期报 E1901“类型尚未支持”，但**解析器、名称解析和类型推导的接口必须对它们是通用的**，后续范式加入时只补求值实现。
- 解析器：手写 Pratt 解析器，错误恢复好、位置信息准。产出 AST 后经过名称解析和量纲推导，再降级成**紧凑的字节码或闭包树**用于求值。

**表达式等价判定**（教学层和验收共用，放在本 crate 中）
- `equiv(a, b, domain, opts) -> EquivResult`：在参数定义域内做**随机数值采样**（默认 64 个点，种子固定），比较两式的相对误差，并要求量纲一致。
- 能判出“代数等价但写法不同”的情况，例如 `η*A*G` 与 `G*A*η`。返回反例点，用于生成提示（“当 A 加倍时，你的式子给出……，而观测是……”）。
- 采样必须覆盖式子用到的全部变量：`domain` 未覆盖时返回 `IncompleteDomain`，不得按 0 代入。
- 含 `time` / `dt` 的式子必须由 `opts.time` / `opts.dt` 给出采样范围；缺失时返回 `Undefined`，不得固定在 0。
- 相对误差的分母为 `max(|l|, |r|, scale)`，其中 `scale` 是输出量的 K13 典型量级；未声明 `scale` 时退化为纯相对误差，不使用固定的 `1.0` 下限。
- 含 `lookup` 的式子必须提供表数据；缺失时返回 `Undefined`，不得按 0 代入。
- 不做完整符号化简，这是刻意的选择。符号代数见 §5.7.6。

### 5.3 模型 schema（`cetus-model`）

模型文件是 YAML，顶层字段 `schema: cetus.model/<版本>`。Rust 类型用 serde 定义，并用 schemars 导出 JSON Schema 到 `docs/schema/model.schema.json`。

**完整示例：太阳能板与蓄电池**（M1 的首个样板，也是 M4 第一课的真模型）

```yaml
schema: cetus.model/0.1
id: energy.solar-battery
version: 1.0.0
title: { zh-CN: "太阳能板与蓄电池", en: "Solar panel and battery" }
tier: empirical                     # empirical | speculative
paradigms: [sd]

time:
  unit: h
  dt: 0.05                          # 宏步长（单范式时即积分步长）
  horizon: 72
  integrator: rk4                   # euler | rk4 | dopri5 | ros2（刚性）

parameters:
  area:            { unit: "m^2",   value: 12,   range: [1, 100],     role: control }
  efficiency:      { unit: "1",     value: 0.20, range: [0.05, 0.47], source: "param:pv.module-efficiency" }
  peak_irradiance: { unit: "W/m^2", value: 1000, range: [0, 1400],    source: "param:solar.peak-irradiance.earthlike" }
  day_length:      { unit: h,       value: 26,                        source: "world:planet.day_length" }
  capacity:        { unit: "kW*h",  value: 20,   range: [1, 200],     role: control }
  load:            { unit: W,       value: 800,  range: [0, 5000],    role: input }   # 由端口驱动

stocks:
  charge:
    unit: "kW*h"
    initial: "0.5 * capacity"
    bounds: { min: 0, max: capacity }      # 编译成不变量，并在数值上钳制（会记一条 clamp 事件）

auxiliaries:
  irradiance: { unit: "W/m^2", eq: "peak_irradiance * max(0, sin(2*pi*time/day_length))" }
  pv_power:   { unit: W,       eq: "efficiency * area * irradiance" }

flows:
  charging:    { to: charge,   unit: W, eq: "if charge < capacity then pv_power else 0" }
  discharging: { from: charge, unit: W, eq: "if charge > 0 then load else 0" }

ports:
  power_out:
    connector: electric_power
    role: producer
    offer: "if charge > 0 then 5000[W] else min(pv_power, 5000[W])"   # 可供功率上限
    dispatch_binds: load                                             # 世界分配下来的实际负荷写入 load

observables:
  charge_pct: { unit: "1", eq: "charge / capacity", display: percent }

invariants:
  - { id: charge-bounds, kind: bounds, expr: "charge >= 0 and charge <= capacity" }

meta:
  authors: ["@handle"]
  sources: ["src:iea-pv-2024"]         # 示例标识，实际条目由专家填写
  assumptions:
    - "辐照度用正弦半波近似日变化，忽略云量与大气质量"
    - "充放电效率视为 1（后续课程引入损耗）"
```

**编译器对这个示例的检查**：流量的量纲（W = 能量/时间）必须等于存量量纲（kW·h = 能量）除以时间；`sin` 的参数无量纲；`efficiency` 的来源能在参数库中解析，且 0.20 落在该条目给出的范围内；端口 `electric_power` 的连接器类型存在，`offer` 的量纲与连接器字段一致。

**schema 的主要区块**（各范式按需出现）

### 5.4 编译流水线与诊断（`cetus-compile`）

```
YAML 文本 ─parse─▶ 原始 schema 结构 ─resolve─▶ 名称/引用解析（参数库、连接器、子模块）
  ─units─▶ 量纲推导与检查 ─structure─▶ 结构检查（循环依赖、端口契约、未用变量）
  ─lower─▶ IR（按范式拆成子系统 + 桥接图 + 状态布局）─▶ 可执行 Plan
```

**IR 设计要点**
- 所有变量在编译期分配到扁平的 `f64` 状态槽位（`StateLayout`）。运行时只按索引访问，不查字符串。
- 辅助变量按依赖关系做拓扑排序；出现代数环（auxiliary 互相依赖）时报错 E3101，并提示用 `smooth` 或 `delay1` 打断，**或者**把相关方程显式放进 `solve:` 区块，由求解服务做隐式求解（K5，M6 起支持）。
- 同一模型的编译结果有**内容哈希**（输入 YAML 规范化之后的 blake3），存档用它锁定所用的模型。

**诊断码**（错误为 E，警告为 W；每个码在 `docs/errors/` 下有一页说明，含“常见原因”和“如何修复”，供 LLM 自动修复）

| 范围 | 类别 | 示例 |
|---|---|---|
| E0xxx | 解析 | E0003 意外的符号 |
| E1xxx | 量纲 | E1203 流量量纲与存量/时间不一致 |
| E2xxx | 引用 | E2101 未定义标识符；E2304 参数来源无法解析 |
| E3xxx | 结构 | E3101 代数环；E3402 端口不满足连接器契约 |
| E4xxx | 数值运行时 | E4001 NaN；E4010 刚性过强，建议用 ros2 |
| E5xxx | 课程 | E5203 洞的目标路径不存在；E5401 教学任务引用的误解不是可运行的模型补丁 |
| E6xxx | 世界 | E6101 组件参数超出包络 |
| E7xxx | 验收 | E7301 误解模型未被检查器区分；E7311 教学任务不存在可行的判别实验 |

### 5.5 协同调度器（`cetus-kernel`）

**模型**：借鉴 FMI 协同仿真主算法（co-simulation master），选择简单、确定、够用的方案。

- 一个仿真由若干**子系统**（subsystem）组成，每个子系统属于一种范式。子系统之间只通过**桥接变量**交换数据。
- 全局使用**固定宏步长** `H`（取自 `time.dt`）。每个宏步：
  1. 按桥接依赖图的**确定拓扑序**依次推进各子系统（Gauss–Seidel 方式：后推进的子系统看到先推进者本步的新输出）。
  2. 依赖图中的环用“滞后一步”打断：环上指定一条边读取上一步的值。编译器自动选边（规则：按子系统 id 的字典序，选序号最大的那条回边），并给出警告 W3201，作者也可以显式指定。
  3. 每个子系统内部可以有自己的子步长：ODE 自适应步长、PDE 按 CFL 条件子步、物理固定 1/60 s 子步……但对外只在宏步边界交换数据。
- **事件**：
  - DES 事件在子系统内部按精确时间戳处理，队列按 K8 的排序键排序，保证确定性。
  - 连续量的阈值事件（零点穿越）在宏步边界检测，在步末触发。**事件时间分辨率 = H**。不做步内插值回滚：教育场景不需要，验收中的步长减半收敛测试（V2）会发现对 H 敏感的模型。
- **玩家操作**：作为带时间戳的 `Action` 进入一个操作队列，只在宏步边界生效。操作序列和种子一起构成可复现的输入。
- **玩家决策点（K9）**：子系统可以发出 `Decision` 事件（例如博弈中轮到玩家出牌、市场中需要玩家报价），分析在这一宏步边界**暂停**，等待对应的 `Action`。决策和其他操作一样写进操作日志，所以回放时不需要等待。

**时间模型（K2）**
- `time.kind`：`continuous`（物理时间，带单位）、`discrete`（迭代步，例如 logistic 映射、Leslie 矩阵、回合制博弈）、`none`（无时间：平衡、优化、几何、结构类问题，只能用非瞬态分析）。
- 时间用**整数刻度计数**表示：`t = t0 + tick × quantum`，每次用乘法算出，不做浮点累加，避免误差漂移。
- **多速率**：子系统可以声明自己的采样周期（例如离散控制器每 0.1 s 执行一次），它与宏步长的比值必须是有理数。调度器用两者的最小公倍数换算到整数刻度。

**分析层（K3）**：模型描述“系统是什么”，**分析**描述“要算什么”。课程、行为测试、验收和 UI 引用的都是“模型 + 分析”。

| 分析 | 作用 | 里程碑 |
|---|---|---|
| `transient` | 瞬态仿真（默认） | M1 |
| `sweep` | 参数扫描（网格、拉丁超立方） | M1 |
| `ensemble` | 多种子蒙特卡洛，输出分布 | M3 |
| `fit` | 参数估计：用观测数据拟合参数（最小二乘） | M3 |
| `steady_state` | 求稳态或平衡点（调用 K5 求解服务） | M6 |
| `optimize` | 在约束下优化目标 | 波次 B |
| `linearize` | 在工作点求雅可比矩阵和特征值（稳定性分析） | 波次 B |
| `frequency_response` | 频率响应（伯德图） | 波次 B |
| `sensitivity` | 敏感性分析（Morris 筛选等） | M11 |
| `bifurcation` | 参数延拓、分岔图 | 波次 C |

```rust
pub trait Analysis {
    fn id(&self) -> AnalysisId;
    fn run(&self, plan: &CompiledPlan, cfg: &AnalysisCfg, io: &mut AnalysisIo) -> Result<Dataset, SimError>;
}
```

**数据集（K4）**：所有仪器和分析的输出都是 `Dataset`：多列带单位的数据，加上若干维度（时间、频率、参数、集合成员编号、网格坐标……）。时间序列只是其中的特例。检查器和前端视图都面向 `Dataset`，而不是面向“时间序列”。

**事件排序键（K8）**：所有离散事件按 `(tick, sub_time, delta, priority, seq)` 排序：
- `sub_time` 用于 DES 中比宏步更细的精确时间；
- `delta` 是零延迟的逻辑轮次（数字电路仿真需要）；
- `priority` 用于同时发生事件的显式先后关系；
- `seq` 是插入序号，作为最后的平局裁决。

M1 就定义这个结构；用不到的字段先填 0。

**核心 trait**（示意，具体签名在 M1 中定稿）

```rust
pub trait Paradigm: Send + Sync {
    fn id(&self) -> ParadigmId;
    /// 把 schema 中属于本范式的部分编译成子系统
    fn compile(&self, spec: &ModelSpec, ctx: &mut CompileCtx) -> Result<Vec<Box<dyn Subsystem>>, Diagnostics>;
}

pub trait Subsystem {
    fn id(&self) -> SubsystemId;
    fn layout(&self) -> &StateLayout;
    fn inputs(&self) -> &[BridgeVarId];
    fn outputs(&self) -> &[BridgeVarId];
    /// 从 t 推进到 t + h。只能读 inputs、写自己的状态和 outputs。
    fn advance(&mut self, t: f64, h: f64, io: &mut BridgeIo, rng: &mut RngStreams, ev: &mut EventSink) -> Result<(), SimError>;
    fn save(&self, w: &mut SnapshotWriter);
    fn load(&mut self, r: &mut SnapshotReader) -> Result<(), SnapshotError>;
}
```

新增范式 = 新增一个实现 `Paradigm` 的 crate，并在注册表里登记。内核其余部分不需要改动。这就是“等模型”的扩展机制。

### 5.6 范式全景与底层兼容性

#### 5.6.1 方法

为了让“覆盖绝大部分理工科与计算社会科学”在架构上成立，我们按**数学结构**（而不是按学科）列出所需的范式。一个学科通常要用到好几种范式，同一种范式也服务于许多学科。随后从全部范式中提炼出内核必须预留的**核心抽象**（K1–K14），并在 M1 中按完整形态设计接口（P13）。

“波次”指 M5 之后、由专家需求驱动的范式扩展批次，见 §12.2。

### 5.7 各范式实现要点

#### 5.7.1 SD / ODE（`cetus-sd`，M1）
- 积分器：`euler`、`rk4`（固定步长）；`dopri5`（宏步内自适应，误差控制参数固定，因此仍然确定）；`ros2`（二阶 Rosenbrock，用于刚性系统：有限差分雅可比 + nalgebra 稠密 LU，适合几百维以内的系统）。
- 存量边界：`bounds` 编译成两样东西，一是不变量，二是数值钳制，每次钳制都记一条诊断事件（钳制过多说明模型有问题，V2 会报警）。
- `delay3` 等函数编译成隐含的内部存量，在 `StateLayout` 里标注为 `hidden`。
- 样板模型（M1 必须实现并有解析解或文献对照）：指数衰减、logistic 增长、SIR、捕食者–被捕食者（Lotka–Volterra，检查守恒量）、库存–订货延迟振荡、RC 充放电、太阳能板与蓄电池。

#### 5.7.2 DES / ABM（`cetus-abm`，M6）
- **存储**：每种 agent 类型一张 SoA 表（每个属性一个 `Vec<f64>` 或枚举 `Vec<u16>`），配合稳定 id 和空闲表。不用通用 ECS 库，因为自写 SoA 更容易做确定性快照。
- **空间**：`grid`（可选环面）、`continuous2d`（均匀网格空间哈希）、`network`（CSR 邻接表，可从 petgraph 构建）。
- **规则**（声明式）：

```yaml
agents:
  villager:
    attributes:
      health: { unit: "1", initial: "uniform(0.8, 1.0)" }
      knows_fire: { type: bool, initial: false }
    rules:
      - id: learn-fire
        on: tick
        when: "not self.knows_fire"
        do:
          - pick: { neighbor_in: village_net, where: "other.knows_fire", as: teacher }
          - if: "teacher and chance(teach_rate * dt)"
            then: [ { set: { knows_fire: true } } ]
activation: random_sequential   # random_sequential | synchronous（双缓冲）
```

- 激活顺序：`random_sequential` 用本步的子流做 Fisher–Yates 洗牌；`synchronous` 读旧状态、写新缓冲区。
- 作者侧逃生口（可选，M6 时写 ADR 决定是否引入）：`script: rhai`。使用它的规则会让模块被标记 `verifiability: reduced`，并强制要求专家审核。优先的做法是扩展声明式规则的表达能力，而不是依赖脚本。
- 性能目标：浏览器中 1 万个简单 agent，每个宏步耗时 < 5 ms。

#### 5.7.3 PDE（`cetus-pde`，M7）
- 一维、二维矩形结构网格，单元中心有限体积法。
- 声明方式：

```yaml
fields:
  T: { unit: K, initial: "293.15[K]" }
equations:
  - "ddt(T) = alpha * lap(T) + q / (rho * c_p)"
boundary:
  left:  { kind: dirichlet, value: "373.15[K]" }
  right: { kind: robin, h: h_conv, ambient: "293.15[K]" }
grid: { nx: 128, ny: 1, dx: "0.01[m]" }
scheme: implicit   # explicit（FTCS，自动按 CFL 子步）| implicit（向后欧拉 / Crank–Nicolson + 共轭梯度）
```

- 算子集合刻意保持有限：`lap`、`grad`、`div`、`advect`（一阶迎风；后续可加限制器）。
- 网格规模上限（浏览器）：二维 256×256。超过就要求降分辨率。
- 测试：一维热传导、扩散、波动方程都有解析解对照，并验证网格加密后的收敛阶。
- 与 SD 的耦合：边界值或源项绑定到桥接变量（例如加热器功率来自 SD），场的积分量（总热量、平均温度）作为输出。

#### 5.7.4 刚体（`cetus-physics`，M9）
- 封装 `rapier2d`，开启 `enhanced-determinism`；**不开** `simd8`；初始值里用到的三角函数改用 nalgebra 的 `RealField` 方法。
- 物体的插入和删除顺序由模型 schema 的声明顺序决定。
- 固定物理子步 1/60 s（游戏时间），宏步内多次子步。
- 对外输出：位置、速度、动量、动能、接触力统计。守恒类不变量（无摩擦时的动量、能量）进入 V2。

#### 5.7.5 学习者代码与算法轨迹（Python / Pyodide，`packages/py-runner`，M8）

**运行方式**
- 学习者写 Python，在专用的 **PyWorker** 中由 Pyodide 执行。Pyodide 体积有几 MB，只在课程需要时懒加载，并用 Service Worker 缓存。
- 每节课声明自己需要预装的包（例如 `numpy`、`pandas`；后续还有 `sympy`），不允许运行时从网络安装包。
- 内核（WASM）与 Pyodide 放在同一个 PyWorker 中，由 JS 同步驱动循环：`kernel.step()` → 读取观测 → 调用 Python 策略 → 写入输入。这满足 K10：Python 只在宏步边界介入。

**轨迹（算法课）**
- 提供一个 `cetus` Python 模块，里面是**带插桩的数据结构**：`Arr`、`Graph`、`Grid`、`Stack`、`Queue` 等。每次比较、交换、访问都产生一条轨迹事件，时间轴就是事件序号。比用 `sys.settrace` 逐行跟踪更简单、更可控。需要逐行步进时，再用 `sys.settrace` 作为可选模式。
- 前端把轨迹渲染成动画，支持步进、回退和断点。
- 课程中的洞可以是一段函数体：检查器用随机输入（来自内核的随机子流）做性质判定（输出有序、是输入的排列、结果满足稳定匹配的定义……），并用插桩数据结构统计操作次数，检查复杂度上界。

**确定性**
- Pyodide 版本锁定。CI 中的验收**用同一版本的 Pyodide（在 Node 中运行）**，而不是本机的 CPython，因为两者的数学库实现不同，结果可能不一致（P4 的精神）。
- 加载时固定哈希种子（`PYTHONHASHSEED=0`）；`random` 由内核下发的种子初始化；`time` 和 `datetime` 中依赖真实时间的函数替换为确定性的桩函数。

**安全**（参考：DEF CON 34 上披露的研究表明，有多款产品只在 Python 层面做的限制，可以经由 `ctypes` 或 Emscripten 导出的函数被绕过，进而访问宿主环境）
- 浏览器端：PyWorker 中**不持有任何凭据或令牌**；通过 CSP 限制 `connect-src`；用允许列表（而不是黑名单）控制可导入的模块；移除 `js` 和 `pyodide.ffi` 的访问路径，并限制 `ctypes`。真正的安全边界是“这个 Worker 里没有值得偷的东西”，而不是 Python 层面的限制。
- 超时：用 Pyodide 的中断缓冲区实现（需要 `SharedArrayBuffer`，即需要 COOP/COEP 响应头）；兜底方案是直接终止 Worker。
- **不自动运行其他玩家的代码**。好友分享的蓝图中如果包含代码，只展示；玩家明确点击后才运行，而且同样在隔离的 Worker 中。
- **服务端不执行玩家提交的代码**。如果将来需要（例如批改），必须放在一次性容器中运行，不能只依赖 Pyodide 沙盒。

#### 5.7.6 推导与符号（`cetus-expr` 扩展，M8）
- **推导检查**：玩家逐行写推导，检查器判定每一行与上一行在声明的假设下是否等价（用 §5.2 的数值等价判定，并检查量纲）。若不等价，指出是哪一步出了问题，并给出反例点。
- **近似步骤**：允许标注“近似”（例如 `sin x ≈ x`），检查器验证在声明的范围内误差小于给定容差。
- **量纲分析课**：利用单位系统，自动检验玩家写出的无量纲组合。
- **CAS（波次 B 引入）**：需要真正的符号运算时（积分、解方程），在 PyWorker 中加载 SymPy（Pyodide 在 M8 已经引入，所以增量成本只是 SymPy 包本身）。CI 中的验收同样用 Pyodide 中的 SymPy。M8 只用数值等价判定，不依赖 CAS。

### 5.8 桥接原语

每个方向 2–3 个，语义在本文档中钉死，不允许各模块自行发挥。

| 原语 | 方向 | 语义 |
|---|---|---|
| `aggregate` | ABM → SD | 每个宏步末，对 agent 表做 `count` / `sum` / `mean`（可带过滤条件），写入桥接变量。SD 侧把它当作 `input` 参数。 |
| `threshold_event` | SD → ABM / DES | SD 变量在宏步末穿越阈值（方向可选：上穿、下穿、双向）时，向目标子系统投递一个事件。带滞回宽度参数，防止抖动。 |
| `drive` | 任意 → 任意 | 把一个子系统的输出变量绑定到另一个子系统的 `input` 参数，可带单位换算和延迟（滞后若干宏步）。 |
| `resource` | 物理 / PDE ↔ SD | 通过连接器类型做守恒耦合：一侧给出“可供量”，另一侧给出“需求量”，由分配器决定实际交换量，双方各自扣减。世界层的端口网络也复用这一机制。 |
| `pool` / `instantiate` | ABM ↔ 物理 | （M9 之后）远处的 agent 以统计量形式存在，需要精细交互时实例化为刚体。 |

### 5.9 随机流

- 全局种子 → 用 blake3 派生出各子流种子：`derive(seed, subsystem_id, purpose, entity_id)`。每个子流是 `ChaCha8Rng`。
- `purpose` 包括 `activation`（激活顺序）、`rule`（规则抽签）、`init`（初始化）、`observation_noise`（观测噪声）、`breakthrough`（原住民突破方向的抽选，§7.13）、`story`（小故事抽选，§7.14）、`consult_variant`（请教事件的变式抽选，§6.8）等。
- 原则：**新增一个 agent 或子系统，不会扰动其他实体的随机序列**。用测试验证：在模型中加入一个无关 agent，其他 agent 的轨迹逐位不变。

### 5.10 仪器与断言

- **探针**（probe）：在每个宏步（或每 k 步）记录指定变量，存入环形缓冲区，前端增量读取。
- **聚合**：直方图、相图（两变量轨迹）、空间快照（场或 agent 位置）。
- **运行时断言**：`invariants` 在每个宏步检查（`conserved_sum`、`bounds`、`monotonic`、`nonnegative`、自定义表达式）。违反时记事件，并按配置选择警告或中止。
- 仪器层是教学可视化与验收共用的同一套机制。

### 5.11 快照与存档

- 快照内容：内核版本、schema 版本、每个模型的 `id@version` 与内容哈希、当前时间、各子系统状态、随机流状态、事件队列、待执行操作队列、世界层状态。仪器缓冲区可选。
- 格式：`postcard` 二进制，外面再套一层 `lz4_flex` 压缩和一个头部（魔数 + 格式版本 + 校验和）。调试时可导出为 JSON。
- **状态哈希**：对规范化的状态（不含仪器缓冲区）计算 blake3，用于确定性测试和回放校验。
- 往返测试：快照 → 恢复 → 再跑 N 步，结果必须与不打断直接跑 N 步逐位一致（proptest 覆盖）。

### 5.12 确定性规则清单（CI 强制）

1. 仿真状态和任何参与迭代的路径**禁止**使用 `HashMap` / `HashSet`，改用 `IndexMap` / `BTreeMap`。在 `clippy.toml` 中配置 `disallowed-types`。
2. 超越函数（`sin cos tan exp ln pow sqrt atan2 ...`）**必须**走 `cetus-math`（内部用 `libm`）。在 `clippy.toml` 中用 `disallowed-methods` 禁用 `f64::sin` 等标准库方法。说明：`sqrt` 在 IEEE 754 下本来就是正确舍入的，但为统一起见也走封装层。
3. 禁用 `mul_add`、relaxed-simd，以及任何“快速数学”选项。
4. 单次仿真的推进是**单线程**的。并行只出现在“多次独立仿真”之间（批跑、平行星球）。
5. 内核中不读取系统时钟，不使用系统随机源。
6. agent 的迭代顺序是稳定的；需要打乱时用种子派生的子流洗牌。
7. 刚体相关规则见 §5.7.4。
8. 浮点数的解析和打印使用 Rust 标准库（正确舍入），不要自己写。
9. **CI 测试**：每个样板模型和每个已发布模块，用 native 和 WASM（Node 或 wasmtime 执行）分别运行固定步数，比较状态哈希，必须完全相同。

### 5.13 WASM 接口（`cetus-wasm`）

接口保持窄，粗粒度调用，以减少跨边界开销。

```ts
  readProbes(ids: Uint32Array, since: number): Float64Array; // 增量读取，作为 transferable 返回
  query(expr: string): number;               // 求一个表达式的当前值（检查器、UI 用）

export function runAnalysis(plan: CompiledPlan, analysis: AnalysisJson, seed: bigint): DatasetHandle; // K3/K4：非瞬态分析
```

- 体积预算（gzip 后）：核心版（SD + ABM + PDE + 教学层 + 世界层）≤ 800 KB。刚体、粒子等较重的范式编译成按需加载的 `cetus-full.wasm` 变体（用 Cargo feature 控制）。Pyodide 是另一个独立的懒加载资源，不计入这个预算。
- 在 Worker 中运行。主线程只负责 UI。

## 6. 教学层（`cetus-lesson` + `packages/lesson-runtime`）

### 6.1 课程 schema

课程引用一个模块作为**真模型**，在此基础上声明：隐藏参数、玩家可用的仪器、带洞的玩家模型、任务、检查器、误解模型和掌握度设置。

**示例：为什么蓄电池会在夜里耗尽**（M4 第一课）

```yaml
schema: cetus.lesson/0.1
id: lesson.energy.battery-night
version: 1.0.0
node: kg:eng.energy.pv-basics
module: energy.solar-battery@^1

objectives:
  - { id: o1, text: { zh-CN: "光伏功率与面积、效率、辐照度成正比" } }
  - { id: o2, text: { zh-CN: "能用存量-流量思想预测蓄电池何时耗尽" } }

truth:
  overrides:
    parameters:
      efficiency: { value: 0.183 }      # “丢失的参数”：玩家要从数据中估计出来

instruments:                            # 玩家只能通过仪器观察真模型
  - { id: lux_meter,     measures: irradiance, every: "0.5[h]", noise: { kind: gaussian_rel, sigma: 0.03 } }
  - { id: power_meter,   measures: pv_power,   every: "0.5[h]", noise: { kind: gaussian_rel, sigma: 0.02 } }
  - { id: battery_gauge, measures: charge_pct, every: "1[h]",   resolution: 0.01 }

player_model:
  base: truth
  holes:
    - id: h_pv
      target: auxiliaries.pv_power.eq
      kind: equation                    # equation | parameter | link | rule | code | derivation
      palette: [efficiency, area, irradiance, "+", "*", "/"]   # 可视化搭建时提供的积木
      hints: [hint.pv.1, hint.pv.2, hint.pv.3]                 # 逐级提示，i18n 键
    - id: h_eff
      target: parameters.efficiency.value
      kind: parameter

tasks:
  - { id: t1, kind: measure,  done_when: "used(lux_meter) and used(power_meter)" }
  - { id: t2, kind: build,    hole: h_pv,  check: { kind: expr_equiv } }
  - { id: t3, kind: estimate, hole: h_eff, check: { kind: param_within, rel_tol: 0.08 } }
  - id: t4
    kind: predict
    prompt: prompt.battery-empty-time
    answer: "first_time(charge <= 0)"
    setup: { params: { load: "1200[W]" }, initial: { charge: "0.3 * capacity" } }
    check: { kind: abs_tol, tol: "1[h]" }
  - { id: t5, kind: fit, check: { kind: trajectory_fit, observable: charge_pct, metric: nrmse, max: 0.05, window: ["0[h]", "72[h]"] } }

misconceptions:                         # 每个误解模型都必须被至少一个检查器拒绝（V4）
  - id: m_square
    note: "认为功率与辐照度的平方成正比"
    source: { kind: hypothesized, ref: null, note: "待 research-misconceptions 调研" }
    patch: { auxiliaries.pv_power.eq: "efficiency * area * irradiance^2 / 1000[W/m^2]" }
    must_fail: [t2, t5]
  - id: m_constant_sun
    note: "忽略昼夜，把辐照度当成常数（日均值）"
    source: { kind: hypothesized, ref: null, note: "待 research-misconceptions 调研" }
    patch: { auxiliaries.irradiance.eq: "peak_irradiance / pi" }
    must_fail: [t4, t5]

mastery:
  node: kg:eng.energy.pv-basics
  maintenance_events: [event.dust-on-panels, event.cloudy-week]

narrative:
  intro: dialog.whale.battery-night.intro
  outro: dialog.whale.battery-night.outro
```

每个误解条目都必须声明来源：

- `source.kind`：`research_documented`（教育研究记录）、`exam_item`（考题中稳定出现的
  错误做法）、`historical_theory`（科学史上的错误理论）、`folk_belief`（民间说法）或
  `hypothesized`（推测）。
- 前四种必须给出 `source.ref: "src:<id>"`；来源库尚未实现，V1 只校验 `src:<id>` 的格式。
- `hypothesized` 的 `ref` 可以为 `null`，但会产生 **W5201** 警告；在模块达到
  `expert_reviewed` 之前必须由专家签字（§8.7）。
- `teaching[].holds` 引用 `hypothesized` 条目时会产生 **W5202** 警告：原住民的误解应
  优先使用有出处的条目（§6.8.2）。

### 6.2 检查器类型

| `check.kind` | 判定方法 |
|---|---|
| `expr_equiv` | 玩家式子与真模型对应式子在参数定义域上做数值等价判定，并检查量纲（§5.2） |
| `param_within` | 玩家估计值与真值的相对或绝对误差 |
| `abs_tol` / `rel_tol` | 预测值与真模型运行结果的比较 |
| `trajectory_fit` | 用玩家模型运行，与观测（带噪声）比较：nrmse、最大偏差、相位误差等 |
| `structure` | 存量-流量图或规则图的结构比较（缺了哪条连接、方向是否正确） |
| `property` | 代码洞：随机输入下的性质判定（有序性、排列关系、复杂度上界……） |
| `derivation` | 推导链逐步等价判定（§5.7.6） |
| `explain` | 选择题或排序题形式的解释检查（不使用 LLM 自由判分） |
| `world_state` | L0：世界中的某个状态是否达标（例如“72 小时内电量从未归零”） |
| `causal_sign` | L1：玩家画出的因果箭头方向（增加 / 减少 / 无关）是否与真模型一致。判定方法：在参数定义域内做弹性或单调性测试（与 V3 共用实现） |
| `discriminating_experiment` | 教原住民（§6.8.3）：玩家选择的实验设置下，真模型与原住民所持误解模型的观测差异，是否明显超出仪器噪声 |

**关于自由文本判分**：运行时不使用 LLM 给玩家的自由回答打分（P1，§1.4）。需要解释性回答时，用结构化题型代替。

### 6.3 观测生成

- 观测 = 真模型运行结果 + 仪器噪声 + 采样间隔 + 分辨率。噪声使用 `observation_noise` 子流，所以同一个存档里观测数据是可复现的。
- 观测**不能**泄露隐藏参数：仪器只暴露 `measures` 中声明的变量。
- 更难的课可以使用间接测量（例如只能测电压和电流，要自己算功率）。
- **以真实数据为真值**（H3）：`truth` 也可以是一个数据集，而不是模型：

```yaml
truth:
  dataset: dataset:climate.global-co2-monthly@1   # 内容仓库 datasets/ 下登记的数据集
```

  数据集条目必须记录来源、许可证、获取日期和预处理脚本（Python，在 CI 的 Pyodide 中可复现）。这类课程里，玩家的模型（或统计分析）直接与真实数据对照。V4 的误解模型和变异测试照常适用；V3 换成“数据集完整性检查”（来源、许可、预处理可复现）。

### 6.4 提示与引导

- **原则：先问，再告诉。** 检查失败时，第一反应不是告诉玩家哪里错了，而是问一个问题，让玩家自己去测、自己发现。自己发现的东西记得更牢（提取练习）。
- 逐级提示（hint ladder），共四级：
  0. **提问**：由检查器的判定结果确定性地生成一个问题，引导玩家去做一次能暴露问题的观测，不透露观测结果。例如：“如果把面积加倍，你的模型会预测功率变成多少？用功率计测一下。”
  1. **方向**：指出应该关注哪个变量或哪段时间。
  2. **关键关系**：给出反例本身。例如：“我们把面积加倍时，你的模型预测功率会变成四倍，但功率计只读到两倍。”
  3. **几乎完整的答案**。
- 第 0 级的生成规则（确定性，不使用 LLM）：
  - `expr_equiv` 失败：取检查器返回的反例点，找出与基准点相比变化最大的输入变量，填入模板“如果把 {变量} 改成 {值}，你的模型会预测 {输出} 是多少？用 {仪器} 测一下。”
  - `trajectory_fit` 失败：取偏差最大的时刻，填入“看看 {时刻} 前后，你的模型和 {仪器} 的读数差在哪里？”
  - `causal_sign` 失败：取方向错误的那一对变量，填入“试着只增加 {原因}，{结果} 会怎么变？”
  - `abs_tol` 失败（预测题）：“先别算，直接运行到 {时刻} 看看。你的预测是偏早还是偏晚？”
  - 课程可以在 `hints` 中为某个洞覆盖第 0 级的模板（i18n 键）。
- **计入掌握度的方式**（工作假设，M3 校准）：第 0 级不计为“使用了提示”，因为它不提供答案信息，只是把探究循环再走一遍；第 1–3 级照常计入，影响 FSRS 的初始评级。
- 同一套阶梯也用于判别实验（§6.8.3）和请教事件。

### 6.5 掌握度、请教事件与运维事件

- 每个节点的掌握度状态用 FSRS 模型表示（稳定度、难度、上次复习时间）。完成课程即为第一次复习，提示使用越多，评级越低。
- 调度放在 TS 层（`packages/mastery`，基于 `ts-fsrs`），因为它依赖真实时间。
- 当某节点的可提取度低于阈值时，调度器向世界注入一次复习。复习有两种形式（具体规则见 §6.8）：
  - **请教事件**：新一代原住民（或别的村子的来访者）带着一个误解来请教，玩家要用判别实验或讲解说服他们。适合 L0–L1 为主的节点。
  - **运维事件**：设施或子代理遇到新情况（光伏板积灰、阴天一周、负荷变化），玩家要诊断原因、调整参数或补充规则。适合有对应设施或子代理任务的节点。
- 事件本身是一个确定性的小场景。完成的质量（是否一次成功、用了几级提示）就是这一次复习的 FSRS 评级。
- 注入方式：调度器把事件作为带时间戳的 `Action` 放进操作队列，在宏步边界生效，写入操作日志（与 §5.5 的玩家操作一致，回放可复现，不破坏 P2）。FSRS 只决定“何时、哪个节点”，**不直接修改任何世界状态**。
- 未处理的运维事件只会让对应设施降级运行，退回黑盒默认供应水平（P8），不会摧毁世界。未处理的请教事件只是在那里等着，没有任何惩罚（§6.8.5）。
- 掌握度按表示层分别记录（§3.6）。请教和运维事件的形式，与玩家已掌握的最高层相匹配。

### 6.6 外部资源与学习记录导出（P16）

- 每个节点带有经过筛选的 `external_resources`（§9.3）：公开课、可视化工具、教材章节、单领域的专门应用。优先选择免费和开放许可的资源，注明语言和难度。资源清单由专家维护，CI 定期检查链接是否失效。
- 在搜索或全图模式中选中一个节点时，同时显示两样东西：“在这里学”的路径，以及“如果你只想学这一门，这些地方更合适”的推荐。
- 学习记录可以导出：已掌握的节点、各层掌握度、FSRS 复习状态。复习卡片可以导出为 Anki 卡组，让玩家带着自己的学习成果离开。

### 6.7 按表示层编写课程

课程在 §6.1 的基础上增加 `layers` 字段。下面是同一节课的 L0、L1、L3 部分；L2 就是 §6.1 中已有的洞和任务。

```yaml
layers:
  L0:
    tasks:
      - id: l0-1
        kind: tinker                       # 直接摆弄世界中的对象
        prompt: prompt.keep-lights-on-at-night
        controls: [area, capacity]
        check: { kind: world_state, expr: "min(charge) > 0", window: ["0[h]", "72[h]"] }
  L1:
    holes:
      - { id: c1, kind: causal_link, from: area, to: pv_power }   # 玩家选择：增加 / 减少 / 无关
      - { id: c2, kind: causal_link, from: load, to: charge }
      - { id: c3, kind: causal_link, from: irradiance, to: charging }
    tasks:
      - { id: l1-1, kind: build, holes: [c1, c2, c3], check: { kind: causal_sign } }
    misconceptions:
      - { id: m_load_helps, note: "以为负荷越大充得越快", patch: { c2: increase }, must_fail: [l1-1] }
  L2:
    inherit: base                          # 即 §6.1 中的 player_model / tasks / misconceptions
  L3:
    tasks:
      - id: l3-1
        kind: code
        prompt: prompt.write-charge-scheduler
        check: { kind: property, spec: spec.scheduler-never-empties }
```

V4 对每个层分别执行（§8.5）。

### 6.8 教学即复习：教子代理与原住民

#### 6.8.1 理念

讲给别人听、帮别人找出错误，是最强的提取练习之一（“教学相长”，也称导生效应）。本项目把它做成核心玩法：学会的东西，要能**教出去**。两类学生对应两种不同的“教”：

| | 子代理 | 原住民 |
|---|---|---|
| 性质 | 机器人，可靠，照做 | 有自己想法的生物，带着误解来 |
| 教的要求 | **精确**：把模型或规则完整地交给它，它按你给的执行 | **说服**：找到对方错在哪，设计一个实验让对方亲眼看到 |
| 对应表示层 | 玩家已掌握的最高层（L0 是“示范操作”，L2 是公式与参数，L3 是 Python 策略） | L0–L1 即可完成；更高层提供更精细的实验与解释 |
| 检查方式 | 复用已有检查器：子代理在若干场景中按玩家给的模型运行，用 `world_state` 判定 | `discriminating_experiment`（§6.8.3） |
| 复习形式 | **运维事件**：子代理遇到新情况（练迁移） | **请教事件**：新一代原住民带着误解来（练提取） |
| 何时可用 | 子代理出现之后（M6 起）；在此之前，“部署进世界”就是同一件事的雏形 | 降落后第二天起（Q21）；最初受语言隔阂限制，以演示和实验为主（Q23） |

教子代理与教原住民都不绕过掌握度检查（P11）：教学任务本身就是检查，而且只能在玩家已通过对应课程之后开启。

#### 6.8.2 课程 schema：`teaching` 区块

课程在 §6.1 的基础上可以增加 `teaching` 区块。下面延续“蓄电池夜间耗尽”一课：

```yaml
teaching:
  - id: teach-natives-1
    learner: native                       # native | subagent
    layer: L0                             # 本任务面向的最低表示层
    holds: m_constant_sun                 # 原住民持有的误解：必须引用一个可运行的模型补丁（misconceptions 中带 patch 的条目）
    claim: dialog.native.sun-never-sleeps # 原住民用自己的话说出这个误解（i18n 键），例如“太阳的力气白天存进石头里，晚上也一直在”
    setup_space:                          # 玩家可以选择的实验设置
      controls:
        load:     { range: ["0[W]", "2000[W]"] }
        capacity: { range: ["5[kW*h]", "40[kW*h]"] }
      initial:
        charge_pct: { range: [0.2, 1.0] }
      instruments: [battery_gauge, lux_meter, power_meter]   # 只能选课程已声明的仪器
      duration: { max: "52[h]" }          # 最多观察两个星球日
    check:
      kind: discriminating_experiment
      min_separation: 4.0                 # 以所选仪器的噪声标准差（或分辨率）为单位
      require_prediction: true            # 实验开始前，原住民会先说出他们的预测（由误解模型算出），玩家可以看到
    on_success: dialog.native.sun-never-sleeps.convinced
    variants: [teach-natives-1b, teach-natives-1c]   # 请教事件复习时使用的变式（§6.8.4）

  - id: teach-natives-1b                  # 变式：同一个误解，换一个情境
    learner: native
    layer: L0
    holds: m_constant_sun
    claim: dialog.native.sun-never-sleeps.rainy-season
    setup_space: { inherit: teach-natives-1, duration: { max: "78[h]" } }
    check: { kind: discriminating_experiment, min_separation: 4.0, require_prediction: true }

  - id: teach-subagent-1
    learner: subagent
    layer: L2                             # 按玩家已掌握的最高层；L0 时改为示范操作
    gives: [h_pv, h_eff]                  # 玩家把这些洞的答案交给子代理，作为它的工作模型
    scenarios:                            # 子代理要用玩家给的模型在这些场景中独立完成任务
      - { id: s1, setup: { params: { load: "900[W]" } } }
      - { id: s2, setup: { params: { load: "1400[W]" }, initial: { charge: "0.4 * capacity" } } }
    check: { kind: world_state, expr: "min(charge) > 0.05 * capacity", window: ["0[h]", "52[h]"] }
    new_situations: [event.cloudy-week, event.dust-on-panels]   # 复习时以运维事件出现（§6.8.4）
```

规则：
- `holds` 引用的误解必须是可运行的模型补丁（`patch` 作用于模型，而不是 L1 的因果箭头补丁），否则报 E5401。L1 的因果误解如果要用于教原住民，需要另写一个与之对应的模型补丁。
- `holds` 引用 `source.kind: hypothesized` 的误解时给出 W5202 警告；原住民的误解应优先使用有出处的条目（`research_documented` / `exam_item` / `historical_theory` / `folk_belief`）。
- 原住民的误解应来自真实的学科教育研究（`design-misconceptions` 技能），并经人工整理成原住民的说法。变异测试自动生成的变体可以用来检验课程，但不直接作为原住民的台词。
- `setup_space` 只能使用课程已声明的仪器和可调参数，不能借此读出隐藏参数（与 V4 的“观测不泄露”一致）。

#### 6.8.3 `discriminating_experiment` 检查器

**判定步骤**（确定性，在 `cetus-lesson` 中实现）：
1. 校验玩家的设置 `s` 落在 `setup_space` 内。
2. 用同一个种子分别运行真模型 `T` 和误解模型 `M = T ⊕ patch`，设置为 `s`，运行到 `s.duration`。
3. 对玩家所选的每个仪器 `i`，在其采样时刻上计算无噪声读数之差，再除以该仪器的噪声尺度 `σ_i`（`gaussian_rel` 取读数乘以 sigma，`resolution` 取分辨率）：
   `sep_i = max_t |y_T,i(t) − y_M,i(t)| / σ_i(t)`
4. `separation = max_i sep_i`。若 `separation ≥ min_separation`，判定通过。
5. 返回结果：是否通过、`separation`、差异最大的仪器和时刻（用于回放与解释）。

**玩家看到的过程**：
- 原住民先说出他们的预测（`require_prediction: true` 时，由误解模型在同一设置下算出，例如“电池整晚都是满的”）。
- 实验在世界中运行，玩家和原住民一起看真实的仪器读数（带噪声的观测，§6.3）。
- 通过时，回放定格在差异最大的时刻，原住民在这一刻“想通了”。这就是 §3.7 所说的“理解的那一刻”，反馈是信息性的（“他们看到了：天黑以后，电池真的在一点点变空”）。
- 未通过时，给出确定性的提示，而不是判错：“在你选的这段时间里，他们的说法和真实情况看起来几乎一样。什么时候两者会差得最远？”提示阶梯与 §6.4 共用。

**教学意义**：设计判别实验是科学方法的核心能力，比“说出正确答案”难一个层次：玩家必须同时在脑中运行正确的模型和对方的模型，找出两者分歧最大的地方。

#### 6.8.4 复习：请教事件与新情况

**请教事件**（原住民线）：

```yaml
# content/world/consults/energy.night-battery.yaml
schema: cetus.consult/0.1
id: consult.energy.night-battery
node: kg:eng.energy.pv-basics
lesson: lesson.energy.battery-night
visitors:                                  # 叙事上是谁来请教（从中按 consult_variant 子流抽选）
  - { who: natives.young-generation, intro: dialog.native.kids-grew-up }
  - { who: natives.neighbor-village,  intro: dialog.native.heard-from-afar }
variant_pool: [teach-natives-1, teach-natives-1b, teach-natives-1c]
avoid_repeat: 2                            # 最近 2 次用过的变式不再抽到
fallback:                                  # 玩家想不起来时，可以先回到课程重温，没有任何惩罚
  reopen_lesson: { layer: L0 }
grading:                                   # 映射为 FSRS 评级
  first_try_no_hint: good
  with_hints: hard
  after_reopen: again
```

- **叙事是代际更替，不是遗忘**：来请教的是新长大的孩子、别的村子听说了来的人，而不是“因为你没回来，村民们都忘了”（§3.7 红线）。
- **变式**：每次复习尽量换一个变式（不同季节、不同负荷、同一误解的不同说法），避免玩家只记住上一次的答案。
- **按层匹配**：玩家已掌握 L2 时，请教事件可以要求更精细的实验（更短的观察窗口、更少的仪器），或要求玩家额外预测“他们会在几点发现电池空了”。

**新情况**（子代理线）：
- 子代理按玩家给的模型工作；复习时以运维事件出现：条件变了（阴天一周、积灰、负荷翻倍），原来的规则不够用了，子代理“来汇报”。
- 这练的是**迁移**而不是单纯回忆：玩家需要判断新情况下模型的哪一部分要调整。子代理不会“忘记”，以免削弱“子代理可靠”的设定。

#### 6.8.5 复习时钟与世界时钟

- **世界时钟**（原住民时钟，§7.12）：原住民的教育存量在 SD 模型中会折旧（§7.7），知识也会在原住民之间通过 ABM 网络扩散（M6）。这是仿真本身，属于社会科学内容，确定性，由内核推进；推进速度由活跃在线时间和时间额度决定。
- **复习时钟**：FSRS 根据真实时间决定何时、哪个节点需要复习，由 TS 层调度，只通过 `Action` 注入请教或运维事件（§6.5）。
- 两者**不互相写入**：FSRS 不修改教育存量；教育存量的变化也不触发 FSRS。它们只在叙事上相接（教育存量低的村落，更可能是来请教的那一个）。
- 离线摘要（§7.8）不把教育存量的折旧描述为“损失”，而描述为自然的代际变化（“村里有一批孩子长大了，他们还没见过夜里的电池”）。
- 原住民时钟因额度用完而停止时，请教事件照常可以发生（复习依赖真实时间，不依赖原住民时钟）；来请教的人就是当前这一代。
- 未处理的请教事件没有期限、没有惩罚；玩家可以说“今天不讲了”，界面不出现任何羞辱或愧疚的措辞。

#### 6.8.6 动机设计评审（P15）

| 测试 | 结论 |
|---|---|
| 透明测试 | 在拆解模式（§3.7）和设置中的“为什么会有人来请教”说明里，直接告诉玩家：请教是复习调度为你安排的，因为讲给别人听是最好的复习。说破之后机制依然有效：讲解与判别实验本身就是有效的提取练习，不依赖玩家“不知情” |
| 生活测试 | 练的是两项可以带出游戏的能力：向别人解释一件事，以及设计一个能区分两种说法的验证方法 |
| 红线对照 | 不把遗忘归咎于玩家缺席；请教没有期限、拒绝没有惩罚；不使用愧疚式推送（例如“村里的孩子在等你”的推送通知不实现） |
| 奖励形式 | 奖励原住民想通的那一刻，反馈是信息性的；不给与教学质量无关的外在奖励 |
| P11 | 教学任务只在玩家通过对应课程之后开启，且本身就是检查；原住民学会后提供的协作收益，不能替代玩家自己的掌握度 |

## 7. 世界层（`cetus-world`）

### 7.1 概念

世界本身就是一个**持久的复合模型**：它的组件是各个模块的实例，通过端口和连接器组成网络。世界层在内核的组合机制之上，再加上持久化、游戏规则（包络、全局修正、事件）和叙事状态。

### 7.2 世界定义

```yaml
# content/world/planet.yaml
schema: cetus.world/0.1
planet:
  day_length: "26[h]"
  gravity: "9.3[m/s^2]"
  regions: [region.landing-site, region.river-valley]   # 随知识图谱增长而增加
ship:
  defaults:                         # 默认供应（黑盒），P8
    - { component: ship.solar-reserve, params: { output_cap: "1500[W]" }, degraded: true }
    - { component: ship.water-recycler }
    - { component: ship.fabricator }
    - { component: ship.rice-reserve, params: { stock: "5[kg]" } }   # 白饭的最初来源
priorities:                         # 资源分配优先级，从高到低
  - life_support
  - ship_repair
  - production
  - comfort
```

### 7.3 连接器与端口网络

- 连接器类型定义在 `content/connectors/*.yaml` 中，例如：

```yaml
id: electric_power
fields:
  offer:    { unit: W, kind: resource, from: producer }
  request:  { unit: W, kind: resource, from: consumer }
  dispatch: { unit: W, kind: resource, to: producer }   # 分配给生产者的实际出力
  grant:    { unit: W, kind: resource, to: consumer }   # 分配给消费者的实际获得量
conserved: true                         # 守恒：Σdispatch == Σgrant（考虑损耗时由线损组件显式建模）
```

- 首批连接器：`electric_power`、`heat`、`water`、`food_energy`、`material:<kind>`、`labor`、`information`。
- **连接器字段的种类（K6）**：每个字段都必须声明 `kind`。上面例子中的字段属于 `resource`（供需分配）。其他种类：
  - `signal`：因果信号，单向传递值（控制信号、传感器读数）。
  - `across` / `through`：非因果连接（波次 B 起实现）。在一个连接节点上，所有端口的 `across` 变量相等（电压、温度、压强、速度），`through` 变量之和为零（电流、热流、质量流、力）。这就是电路、热网络、液压网络、机械网络共用的形式（A4）。

  M4 只实现 `resource` 和 `signal`，但 schema 和编译器从一开始就要求每个字段声明 `kind`，以免将来做不兼容的修改。

```yaml
id: electrical_pin            # 波次 B 的非因果电路连接器示例
fields:
  v: { unit: V, kind: across }
  i: { unit: A, kind: through }
```
- 每个宏步，世界层对每个连接器网络做一次**确定性分配**：按优先级从高到低满足需求；同一优先级内按比例分配；储能组件可以同时作为生产者和消费者（充电优先级最低）。分配算法要满足守恒，并有单元测试。

### 7.4 组件实例

- 组件实例 = `module_id@version` + 内容哈希 + 参数集 + 状态 + 在地图上的位置或槽位。
- 每个实例有稳定的 `instance_id`。
- 来源标签：`default`（飞船黑盒）、`native`（原住民传统技艺，黑盒）、`player`（玩家学会的白盒）、`blueprint`（好友蓝图，但仍需玩家掌握后才能改进）。
- 玩家的白盒组件可以替换或并联黑盒组件。

### 7.5 全局修正（基础学科）

- 基础学科节点（数学、物理……）提供有渐近上界的修正值，例如：

```yaml
# content/world/modifiers.yaml
- id: coordination_efficiency
  applies_to: [subagents, natives]
  formula: "1 + 0.5 * (1 - exp(-0.3 * mastery_sum(tier: foundation, domain: math)))"
  cap: 1.5
- id: subagent_cap
  formula: "2 + floor(4 * (1 - exp(-0.25 * mastery_sum(tier: foundation, domain: physics))))"
```

- `mastery_sum` 取的是各节点当前的掌握度（0–1），所以修正值会随遗忘而轻微回落，鼓励复习。

### 7.6 包络（有界改进，P9）

```yaml
# content/world/envelopes.yaml
- id: pv.module-efficiency
  param_ref: "param:pv.module-efficiency"
  levels:                               # 按知识深度逐级放开上限
    - { requires: [kg:eng.energy.pv-basics],        max: 0.22 }
    - { requires: [kg:phys.modern.pn-junction],        max: 0.26 }
    - { requires: [kg:eng.energy.multijunction-cells], max: 0.40 }
  hard_cap: 0.47                        # 物理与文献给出的上限，任何情况下不能超过
```

玩家组件的参数在部署时由世界层检查；超出包络会被拒绝（E6101），并提示需要学习哪个节点才能放开上限。

### 7.7 角色与群体

- **鲸鱼娘**（玩家化身）：俯视角的轻量角色，本质上是“会走路的光标”。状态包括电量、维护度、增益（如白饭）。不做复杂动画。
- **子代理**：ABM agent，有任务队列（采集、搬运、建造、维护）。数量上限来自全局修正 `subagent_cap`。子代理执行的模型或规则来自玩家的教学（§6.8）；遇到新情况时以运维事件的形式回来汇报。
- **原住民**：
  - 宏观层：SD 模型，包括人口（logistic 增长，承载力由食物、居住、医疗决定）、信任存量、语言互通程度、教育存量（知识会折旧）。
  - 微观层：村落尺度的 ABM（几十到几百个个体），用于社交网络、知识扩散、语言演化。
  - 关系是合作互惠的：鲸鱼娘提供的帮助（医疗、粮食、知识）会提高信任和福祉；原住民提供劳动、本地知识和创造性洞见。
  - **教原住民**（§6.8）：原住民带着误解来，玩家用判别实验说服他们。成功的教学提高对应村落的教育存量和信任。新一代长大、别的村子来访，是请教事件（复习）的叙事来源。教育存量的折旧和扩散由仿真决定，与 FSRS 调度分开（§6.8.5）。
  - **原住民的科技与天才**（§7.13）：原住民有**自己的已点亮节点集合**，在同一张科技网络上独立推进。研究进度确定性地累积，进度满了就发生一次突破，由一位具名的原住民天才完成；突破的方向从原住民自己的科技前沿中加权抽选（`breakthrough` 子流）。原住民发展出的技术，对玩家而言是黑盒（`native` 来源）；玩家之后仍然可以学习这个节点，把它换成白盒并改进（与 P8、P11 一致）。
  - **寿命与代际**：代际约 3–5 个原住民年（工作假设，见 §3.1），人口模型按此参数化。
  - **多个部族**（Q30，后续设计）：原住民可能有多个部族，部族之间的关系用复杂网络与博弈建模。M4–M6 只实现一个部族，但原住民相关的状态、节点集合、请教事件与小故事都要带 `tribe` 字段（先只有一个取值），为以后留扩展点。

### 7.8 离线时间

- 玩家在设置中选择**离线时世界是否流逝**（§7.12.4）。默认值待定（Q25）。
- **不流逝**：离线期间世界完全暂停，回来时一切如旧。
- **流逝**：回到游戏时，用聚合层的简化模型（只跑 SD 宏观层，粗步长）快进。快进消耗时间额度，并有单独的上限（`offline_max`，工作假设 1–2 个原住民年）。离线期间原住民的研究只按“无人支持”的基础速率推进（§7.13.2），所以离线带来的科技进展很少。
- 离线快进中，生命维持类需求永远优先满足，不会发生灾难性事件。
- 回到游戏时给出一份“你离开期间”的摘要（产量、库存变化、原住民的小故事、待处理的运维事件和请教事件）。摘要**不是领取界面**：没有“领取”按钮，没有要点击才能拿到的东西。摘要不把教育存量的变化描述为损失（§6.8.5）。

### 7.9 平行星球（M11）

- 对当前存档做快照，分叉出 N 个（浏览器中 N ≤ 4）副本，各自施加参数或制度覆盖。
- 在 BatchWorker 中无头运行到指定时间，然后在对比视图中并排显示仪器数据。
- 分叉不会写回主存档，除非玩家选择“采纳这个分支”（实证区允许，假想实验室不允许）。

### 7.10 存档

- M4：IndexedDB（Dexie），保存最近 3 个版本，并支持导出、导入 `.cetus-save` 文件。所有存储读写都包 try/catch；存储不可用时提示玩家导出存档。
- M10：云同步。同一份二进制快照上传到对象存储，带版本号和冲突检测（以最后写入为准，并保留冲突副本）。
- 加载时：检查内核版本和模块版本，必要时依次执行 schema 迁移和模块迁移，然后重新编译。

### 7.11 阶段目标与能力

- **能力**（capability）是世界可测量的本领，例如“每个星球日能生产多少千克推进剂”。每项能力分若干等级，每个等级对应世界中的一个可测阈值（能力目录见 §9.4）。
- 节点通过 `provides` 声明它在哪一层提供哪项能力的哪个等级（§9.3）。默认供应（黑盒）也提供能力，但通常只到最低等级。
- 能力之间的依赖（例如电解制推进剂需要充足的电力）由世界模拟本身体现，**不**写成网络中的先修边。
- **目标**按能力需求定义：

```yaml
schema: cetus.goal/0.1
id: goal:phase1.return-launch
title: { zh-CN: "子代理驾驶飞船返航" }
requires:                                  # provenance：哪些来源可以满足这项能力（§7.13.3）
  - { cap: "cap:propellant.production",   min_level: 1, provenance: [player, native_developed] }
  - { cap: "cap:propulsion.delta-v",      min_level: 1, provenance: [player, native_developed] }
  - { cap: "cap:control.attitude",        min_level: 1, provenance: [player, native_developed] }
  - { cap: "cap:autonomy.pilot",          min_level: 1, provenance: [player] }   # 驾驶员只能是玩家的子代理
  - { cap: "cap:structure.airframe",      min_level: 1 }                          # 不写 provenance = 任何来源都可以，包括黑盒
  - { cap: "cap:navigation.launch-window", min_level: 1 }
  - { cap: "cap:comms.link",              min_level: 1 }
budget:                                    # 工作假设，M4 后校准
  nodes: [50, 100]
  hours_L0_L1: [12, 25]
  weeks: [6, 10]
  native_years: [24, 50]                   # 主线期间原住民经历的年数（§7.12）
routes:                                    # 各路线的原住民年数锚点（§7.13.4），graph check 用模拟校验
  - { id: mainline,        player_learns: all,         native_support: any,  native_years: [24, 50] }
  - { id: native-support,  player_learns: pilot_only,  native_support: full, native_years: [60, 100] }
  - { id: minimal,         player_learns: pilot_only,  native_support: none, native_years_min: 2000 }   # 渐近线，在实践中等不到
capstone: "sim:launch-campaign"
spine: "spine:phase1"                      # 规范路线，挂剧情节点（§9.5）
```

- `provenance` 列出可以满足这项能力的来源：`player`（玩家自己掌握的节点，白盒）、`native_developed`（原住民通过自己的研究发展出来的技术，§7.13.3）。不写 `provenance` 表示任何来源都可以，包括飞船残存系统等黑盒。好友蓝图永远不单独满足 `provenance` 要求（P11）。
- 第一阶段有四项能力要求非黑盒来源：推进剂生产、推力与速度增量、制导与控制、子代理驾驶员。前三项可以由玩家或原住民提供，按任意比例组合（**原住民路线**，§7.13）；**驾驶员只能是 `player`**，是叙事上的要求：最后驾驶飞船回家的，必须是玩家自己理解了才造得出来的子代理，而原住民寿命太短，无法完成远距离的星际航行。“子代理驾驶员”能力的达成，也就是玩家把返航所需的模型逐一教给子代理（§6.8）。
- 因为驾驶员始终由玩家提供，所以**不存在纯原住民路线**，实际都是混合路线：玩家亲自学得越少，就要等原住民发展越久（§7.13.4）。
- **结局演练**（capstone）：一个把所有能力耦合在一起的发射模拟。失败是确定性的，并给出可解释的原因（“推进剂够了，但姿态控制在跨音速段发散了”），指向下一步该学什么。
- **节点粒度**：一个节点 ≈ 一次 10–15 分钟的会话能完成的一个可检验的理解。预算中的数字由这个粒度推出，M4 结束时用实测数据校准。

### 7.12 时间尺度与时间额度

#### 7.12.1 三种时间尺度

| 尺度 | 单位 | 在哪里运行 | 由什么推进 |
|---|---|---|---|
| 实验时间 | 小时、星球日 | 课程的实验台、运维事件、判别实验 | 玩家在实验中按播放 / 快进；是独立的沙盒，不推进世界日历 |
| 世界时间（原住民时钟） | 季度、原住民年 | 世界视图：设施、原住民人口、经济、研究 | **活跃在线时间**：每 7.5 分钟活跃时间 ≈ 1 个季度（`season_minutes`，工作假设）；受时间额度约束 |
| 真实时间 | 天、周 | FSRS 复习调度、时间额度的累积 | 现实日历 |

- 世界只有一本日历。世界视图以季度尺度推进；在季度尺度上，设施层可以按全精度快速运行（一种“延时摄影”），也可以用日均值聚合运行，以性能为准（世界宏步的选择写 ADR）。两种方式在同一存档内必须固定，以保证确定性。
- 课程里的小时级仿真（例如蓄电池的昼夜）是**实验沙盒**：它模拟的是“典型的一天”，不推进世界日历。课程通过后，玩家的白盒部署进世界，在世界的季度尺度上运行。
- 星球的公转周期在 `planet.yaml` 中定义（`year_length`），一个季度 = 四分之一个星球年。
- 时间按活跃在线时间推进（页面在前台、玩家最近有操作），而不是按会话次数推进，以防止反复开关页面刷时间。
- 世界时间的推进作为带时间戳的 `Action` 进入操作日志（例如 `advance_world { seasons: 0.25 }`），回放可复现（P2）。真实时间只存在于 TS 层。

#### 7.12.2 季度更替

- 季度更替**只在课程之间结算**：玩家在课程或判别实验中时，世界时间照常累积，但更替推迟到退出课程时执行，不打断学习。
- 每次季度更替产生一份**季度报告**：收成、人口、原住民的研究进度、本季的小故事（§7.14）、新的突破。会话结束时如果有未读的报告，作为会话摘要展示。季度更替是会话的**自然停止点**（§3.7）。
- **序章**（Q24 已定）：降落、架设设施、第二天遇到原住民、以及之后的新手教程，以叙事节拍推进日历（以天为单位）。**新手教程完成之后**（晚于第一次相遇），原住民时钟才开始按季度运行。序章覆盖哪几节课、大约几次会话，见 Q31。

#### 7.12.3 时间额度

```yaml
# content/world/time.yaml（全部是可调参数，M4 校准）
season_minutes: 7.5            # 活跃在线时间多少分钟 ≈ 1 个季度
allowance:
  accrual_per_day: "1[year_native]"    # 每个现实日累积 1 个原住民年（约 30 分钟活跃时间）
  bank_max: "7[year_native]"           # 最多累积一周的额度，不规律的玩家不吃亏
  daily_use_max: "2[year_native]"      # 单日最多使用的额度（防沉迷），工作假设
offline_max: "1.5[year_native]"        # 离线快进的单独上限（选择“离线时世界流逝”时）
```

- 额度只约束**原住民时钟**。额度用完后，村子“入夜”：原住民不再推进，但课程、设施维护、编年史、科技网络都照常可用。**学习永远不被限制**（§3.7）。
- 到达额度时，鲸鱼娘用温和的语气提出停止点（例如“村子已经睡了，我们也差不多了吧”），不使用倒计时、不使用“还剩 X 分钟”的催促。
- 额度可以累积到 `bank_max`，所以每周只玩一两次的玩家，与每天玩的玩家得到的原住民时间相同。
- 额度在界面上以中性的方式显示（例如“这周村子还能过 3 年”），不做成需要“补满”的进度条。
- 如果将来在有防沉迷法规的地区运营，法规要求与本节的自愿设计是两回事，需要另外满足（Q8）。

#### 7.12.4 离线时间开关

- 设置中的“离线时世界继续”：开启时，离线期间按 §7.8 快进（消耗额度，有 `offline_max` 上限）；关闭时，离线期间世界完全暂停。默认值待定（Q25）。
- 两种选择的长期结果相同：离线快进只按“无人支持”的基础速率推进研究，额度不会因为离线而被浪费（关闭时额度照常累积到 `bank_max`）。这个开关只影响“回来时世界是否已经变了”的感受，不影响进度。

### 7.13 原住民研究与原住民路线

#### 7.13.1 原住民的科技前沿

- 原住民有自己的节点状态集合（已点亮、前沿），存在世界状态中，与玩家的掌握度分开。
- 原住民的前沿 = 先修已被原住民点亮的节点。原住民不使用 L0–L3 表示层的概念，只记“已点亮”。
- 原住民点亮的节点在玩家的科技网络上以单独的样式显示（“原住民在研究的东西”），并照亮附近的迷雾（§9.6）。

#### 7.13.2 研究模型：进度确定、方向随机

- **研究进度**（确定性 SD 存量）：每个季度的增量取决于原住民的研究人口、教育存量、粮食盈余释放出的劳动力、健康水平，以及玩家本季度的支持（教学、援助）。没有玩家支持时，增量是一个很低的基础速率。

```yaml
# content/world/native-research.yaml（结构示意，具体函数形式与参数由专家给出：TODO(expert)）
progress_rate: "base_rate + k_edu * education_stock * researchers^alpha * surplus_labor_factor * health_factor"
breakthrough_cost: "cost(node)"          # 每个节点的突破成本，随节点深度增加
direction:
  candidates: native_frontier
  weights:                               # 引导：玩家教过的领域、原住民当下的需要、与已点亮节点的关联
    taught_domains: 3.0
    current_needs: 2.0
    adjacency: 1.0
  disclose_probabilities: true           # 抽选概率在界面上公开
```

- **何时突破是确定的**：研究进度达到下一个节点的成本，就一定发生一次突破。界面显示进度和预计季度数。
- **突破什么是随机的**：从原住民前沿中按权重抽选（`breakthrough` 子流），权重受玩家引导影响，概率公开。
- **天才是叙事化身**：每次突破由一位具名的原住民天才完成，带着他自己的小故事进入编年史（§7.14）。没有稀有度。
- 玩家的支持只能通过掌握度门控的行为产生（教学任务、部署白盒设施、援助需要相应能力），不能通过单纯的在线时长产生（P11）。

#### 7.13.3 原住民发展的技术与 `provenance`

- 原住民通过研究点亮的节点，可以作为 `native_developed` 来源提供能力（§7.11）。对玩家来说它们仍是黑盒：玩家可以随时学习同一节点，换成白盒并改进。
- `native_developed` 的能力等级由原住民的研究深度决定，同样受包络约束（§7.6）。
- 原住民的发展有代价：资源消耗、环境、分配不均都在模型中真实存在，玩家能看到“推得太快”的后果。具体机制随原住民社会模型一起设计（Q11）。

#### 7.13.4 路线锚点与校准

| 路线 | 玩家亲自学的 | 对原住民的支持 | 原住民年数（工作假设） | 在每周 7 年额度下的现实时间下限 |
|---|---|---|---|---|
| 主线 | 全部所需能力 | 任意 | 24–50 年 | 由学习进度决定，约 6–10 周 |
| 充分支持原住民 | 只学驾驶员相关 | 充分（学完原住民支持线） | 60–100 年 | 约 9–15 周 |
| 最少投入 | 只学驾驶员相关 | 无 | ≥ 2000 年 | 在实践中等不到（P11 的渐近线） |

- 这张表的数字在 M4（主线）和 M6（原住民研究模型）之后用实测与模拟校准。
- `cetus graph check` 对每条路线用原住民研究模型做蒙特卡洛模拟（固定种子集），报告达成目标的原住民年数分布（中位数、90 分位），并与锚点比较（§9.3）。
- 设计意图：充分支持原住民的路线是一条真实可走、但比主线慢的路线；能否真有玩家走完，M6 之后用试玩观察。

### 7.14 小故事与村落编年史

#### 7.14.1 原则：小故事是邀请，不是奖励

- 每个季度报告里有一到两个原住民的小故事。故事的核心是一个**现象**，而这个现象指向玩家还没学的东西。回来的理由是好奇，而好奇直接通往学习（§3.2 的“观察现象”）。
- 故事**没有稀有度**：不分普通和稀有，不用颜色或特效暗示“这次抽到好的了”。
- 故事**不会过期**：全部收进“村落编年史”，随时可以回看，没有错过的焦虑。
- 故事没有“领取”动作，不发放任何资源。

#### 7.14.2 原住民的猜想

- 部分故事带有原住民对现象的**猜想**：错，但不是错得离谱。优先采用人类历史上真实出现过、在有限证据下合理的错误理论（例如热质说、“自然厌恶真空”、自然发生说、燃素说），以及学科教育研究中记录的常见误解。
- 能写成可运行模型补丁的猜想，就写成补丁：它就是一个误解模型，玩家追下去，就是一次判别实验（§6.8）。写不成补丁的猜想只作为故事，不进入教学任务。
- **有时原住民是对的**：一部分故事里，原住民的土办法或猜想其实是对的，而“显然的科学解释”反而不对。比例由内容设计决定（工作假设：约十分之一到五分之一）。目的是让玩家养成“先检验，再下结论”的习惯，也体现原住民作为伙伴的尊重。
- 语气上，原住民的猜想要写得认真、有道理，不能写成笑话。

#### 7.14.3 生成与入口

```yaml
# content/world/stories/river-ice-early.yaml
schema: cetus.story/0.1
id: story.climate.river-ice-early
when: "season == winter and climate.cold_anomaly > 0.5"   # 由世界状态决定是否进入候选池
weight: 1.0
text: dialog.story.river-ice-early                           # 现象的描述（i18n 键）
conjecture:                                                  # 可选：原住民的猜想
  text: dialog.story.river-ice-early.red-star
  correct: false
  misconception: null                                        # 能写成模型补丁时，引用某节课的误解模型（例如 lesson.x#m_y）
leads_to: ["kg:earth.climate.orbit-seasons"]                 # “去看看”的入口；节点不存在时转为研究请求（§3.3）
```

- 候选池由世界状态（季节、气候、人口、原住民科技、玩家已点亮的节点）筛选，再用 `story` 子流按权重抽选，可复现。
- 每个故事都有“去看看”的入口，指向对应的节点，可以穿透迷雾（P16）；节点还不存在时，入口变成一条研究请求。
- 原住民的突破（§7.13.2）也以小故事的形式进入编年史，由完成突破的天才讲述。
- 小故事的文本由内容管线产出（§11.3 的 S5），使用技能 `write-native-stories`，并经人工审核。

#### 7.14.4 动机设计评审（P15）

| 测试 | 结论 |
|---|---|
| 透明测试 | 直接告诉玩家：小故事是为了让你好奇，并且每个故事都通往一个可以学的东西。说破之后依然有效，因为好奇本身是真实的 |
| 生活测试 | 练习从现象出发提出问题，以及用证据检验一个看似合理的说法 |
| 红线对照 | 没有稀有度、不会过期、没有领取动作、与金钱无关 |

## 8. 验收体系

### 8.1 总览

验收分为 V0–V6 七级，由 `cetus verify --level Vn` 执行（V6 是人工流程）。每一级都包含前面所有级别。

| 级别 | 名称 | 自动化 | 抓什么 |
|---|---|---|---|
| V0 | Schema | 全自动 | 格式错误、缺字段 |
| V1 | 静态 | 全自动 | 量纲、引用、结构、端口契约、来源存在 |
| V2 | 数值 | 全自动 | NaN、发散、不变量违反、步长敏感、不确定性 |
| V3 | 参照行为 | 全自动（测试由人写或机写人审） | 数值来源不符、违反已知定性或定量规律 |
| V4 | 教学有效性 | 全自动 | 课程不可解、检查器区分不了误解、教学任务无可行的判别实验 |
| V5 | 平衡与漏洞 | 全自动 | 超出包络、可被利用的刷数值漏洞 |
| V6 | 人工审核 | 人工（可先由 LLM 预审） | 科学正确性、教学质量、表述 |

### 8.2 V1 静态检查

- 所有标识符和引用都能解析；参数来源能在 `content/params/` 或 `content/sources/` 中找到。
- 量纲一致。
- `role: fixed` 的参数必须有 `source`；值落在来源给出的范围内。
- 端口满足连接器契约（字段、单位、方向）。
- 课程中的洞指向存在的路径；误解补丁能成功应用并编译通过。
- `teaching` 区块引用的误解是可运行的模型补丁（E5401），`setup_space` 中的仪器和参数都在课程中声明过，变式与请教事件引用的任务都存在。

### 8.3 V2 数值检查

- **多种子 × 参数扫描**：在 `range` 内用拉丁超立方采样（默认 64 组），每组跑 4 个种子。任何一组出现 NaN、Inf、不变量违反都算失败。
- **步长收敛**：用 `dt`、`dt/2`、`dt/4` 分别运行，关键观测量的差异必须单调缩小，且 `dt` 与 `dt/4` 的结果差在容差内（默认 nrmse < 1%）。这能抓出事件时间分辨率问题和数值伪影。
- **钳制计数**：存量边界钳制的次数超过阈值时给出警告。
- **确定性**：同种子运行两次，状态哈希相同；native 与 WASM 的状态哈希相同。

### 8.4 V3 参照行为测试

模块目录下的 `tests/behavior.yaml`：

```yaml
tests:
  - id: linear-in-area                  # 弹性测试：面积加倍，功率加倍
    kind: elasticity
    input: area
    output: "mean(pv_power)"
    expect: 1.0
    tol: 0.02
  - id: daytime-only-generation
    kind: assert
    run: { until: "72[h]" }
    expr: "max_where(pv_power, irradiance == 0) == 0"
  - id: empties-at-night
    kind: range
    setup: { params: { load: "1200[W]" }, initial: { charge: "0.3 * capacity" } }
    expr: "first_time(charge <= 0)"
    between: ["13[h]", "26[h]"]
    source: "derived: hand calculation in README.md §2"
  - id: matches-analytic                # 有解析解时必须对照
    kind: analytic
    observable: charge
    formula: "..."
    metric: nrmse
    max: 0.001
```

- 测试类型：`assert`、`range`、`elasticity`、`monotonic_in`（某输出随某输入单调）、`analytic`、`golden`（与已审核过的黄金轨迹做回归比较）、`literature`（与文献数据点对照，必须附来源）。
- 实证区模块至少要有：1 个弹性或单调性测试、1 个定量测试（解析解或文献数据），以及黄金轨迹。

### 8.5 V4 教学有效性

对每节课自动执行：
1. **可解性**：用真模型的式子和参数填满所有洞，所有任务的检查必须通过。
2. **区分力**：每个误解模型都必须让 `must_fail` 中列出的检查失败。
3. **变异测试**：自动对真模型中被挖洞的表达式做变异（替换运算符、删除一项、指数改变、交换变量），生成 N 个（默认 50 个）变异体，统计被检查器拒绝的比例（**变异杀伤率**），要求 ≥ 80%。杀伤率低，说明观测设计不足以区分错误模型，需要加仪器或改任务。
4. **观测不泄露**：参数洞对应的参数不能被任何仪器直接读出（否则任务就是抄数）。方程洞允许测量方程左边的变量，因为规律本来就是从输入输出数据中归纳出来的。
5. **噪声稳健**：换 8 个噪声种子，可解性和区分力的结论保持不变。
6. **逐层执行**：以上检查对课程提供的每个表示层分别执行。L1 的误解模型是错误的因果方向；L1 的变异测试是随机翻转因果箭头的方向。
7. **教学任务**（`teaching` 区块，§6.8）：
   - **判别实验可解性**：对每个 `discriminating_experiment` 任务及其每个变式，在 `setup_space` 内做搜索（网格加拉丁超立方，默认 256 组设置），至少存在一组设置使 `separation ≥ min_separation`，否则报 E7311。
   - **不太容易**：可行设置的比例不应接近 100%（默认上限 90%），否则任务退化为“随便做个实验都行”，给出警告；也不应低于 2%，否则给出警告，提示扩大 `setup_space` 或增加仪器。
   - **误解本身不能通过**：把误解模型当作真模型时，原住民的预测与它自己的观测一致（自洽性检查，防止补丁写错）。
   - **噪声稳健**：换 8 个噪声种子，找到的可行设置在带噪观测下依然能让差异被看出来。
   - **子代理任务可解性**：用真模型的答案作为 `gives`，所有 `scenarios` 的检查都通过；用该课至少一个误解模型作为 `gives`，至少一个场景失败。

### 8.6 V5 平衡与漏洞

- 组件参数在包络之内。
- **红队搜索**：在世界的一个标准测试场景中，对玩家可控参数和操作序列做随机搜索加简单的进化策略（预算固定，例如 2000 次评估），最大化指定的世界指标（如净发电量、粮食产量）。结果不能超过该指标的理论上界（由包络推出），也不能出现 NaN 或负库存。
- 世界中引入新组件后，对标准存档做 7 个星球日的回归运行，关键经济指标的变化在预期范围内。
- **路线检查**（§7.13.4）：用原住民研究模型模拟各路线，任何路线都不能以明显少于锚点的学习量或原住民年数达到阶段目标；“最少投入”路线的原住民年数中位数不得低于锚点下限。新增原住民研究相关内容（节点成本、权重、援助效果）时必须重跑。
- **挂机检查**：模拟一个只在线、不做任何掌握度门控行为的玩家，在额度允许的最大速度下运行，原住民研究进展必须落在“最少投入”路线的速率内。

### 8.7 V6 人工审核与可信等级

- **LLM 预审**：使用与生成者**不同的模型**，按 `skills/review-module/CHECKLIST.md` 逐项审查，输出结构化报告附在 PR 上。预审只用于辅助，不能替代人工。
- **专家审核**：专家在 `reviews/<module-id>.yaml` 中签名（姓名或 handle、日期、审核范围、意见）。
- **可信等级**（在 UI 上以徽章展示）：

| 等级 | 条件 | 可见范围 |
|---|---|---|
| `draft` | 未通过 V5 | 只在开发预览中可见 |
| `machine_verified` | 通过 V0–V5 + LLM 预审 | “社区预览”分支，标注“机审” |
| `expert_reviewed` | 再加至少 1 位相应领域专家签名 | 实证科技树主线 |

- **假设性误解来源**：`source.kind: hypothesized` 的误解，在模块达到
  `expert_reviewed` 之前必须由专家在 `reviews/<module-id>.yaml` 中签字确认；在此之前
  只能用于 `draft` / `machine_verified` 预览，不得进入主线。M3 只写规则并产生 W5201，
  不实现自动检查。

### 8.8 假想实验室的特殊验收

假想学科没有现实中的真值，所以 V3 换成以下要求：
- **假设清单**（`assumptions.yaml`）：每条假设包括 id、陈述、在模型中的落点（哪个参数或规则）、现实对照物、是否有争议。
- **自动敏感性分析**：对每条假设对应的参数做 Morris 筛选（或单因素扫描），计算哪些假设会**翻转结论**（结论在 `conclusions.yaml` 中定义为可计算的指标比较）。
- UI 必须展示“这个结论依赖于：A3、A7”，并允许玩家修改这些假设，看结论如何翻转。
- 表述上不使用规范性结论（“X 制度更好”），只呈现各项指标的权衡。
- 涉及现实政治、宗教、民族议题的内容需要人工审核，不能只靠机审发布。

### 9.3 科技网络节点

科技网络是一般的有向网络，不是树。节点 schema 为 `cetus.node/0.2`。领域分类、ID 规则和调研流程，见 `skills/cetus-knowledge-network/SKILL.md`。

```yaml
schema: cetus.node/0.2
id: "kg:eng.energy.pv-basics"          # kg:<领域>.<子领域>.<短名>；发布后永不复用

title: { zh-CN: "光伏发电基础", en: "Photovoltaics basics" }

  L0: { minutes: 10 }
  L1: { minutes: 10 }
  L2: { minutes: 15 }
requires:                              # 硬先修，按层声明；高层自动包含低层的要求
  L0: []
  L1: []
  L2:
    all:
      - "kg:math.func.proportionality@L2"
      - any: ["kg:phys.energy.power@L2", "kg:phys.energy.power@L1"]
enhances: [{ node: "kg:eng.energy.pv-tilt", note: "倾角决定入射辐照度" }]   # 软边：学了更好，不是先修
applies_to: ["kg:eng.aero.spacecraft-power"]
analog_of: []
provides:
  - { cap: "cap:power.generation", levels: { L1: 1, L2: 2 } }
paradigms: [sd]
lessons: [lesson.energy.battery-night]
consults: [consult.energy.night-battery]   # 本节点的请教事件（§6.8.4），可选
world_effects:
  improves: [{ component: ship.solar-reserve, envelope: pv.module-efficiency }]

  - { title: "TODO", url: "TODO", kind: course, lang: en, level: intro, free: true }

```

**边的类型**

| 边 | 含义 | 用于 |
|---|---|---|
| `requires` | 硬先修（不学就无法开始这一层） | 可学性判定、最小路径、迷雾 |
| `enhances` | 学了更好，但不是必须 | 推荐、轮廓相关度 |
| `applies_to` | 应用关系 | 推荐、能力推导 |
| `analog_of` | 数学结构相同（例如热传导与扩散、RC 电路与牛顿冷却） | 推荐、跨领域迁移提示 |

**网络规则**（`cetus graph check` 检查）：
- 每一层的硬先修关系各自构成有向无环图（DAG）；高层的先修集合包含低层的先修集合。
- L0 和 L1 的先修要尽量少；主线节点的 L0–L1 不得依赖任何节点的 L2 及以上层。
- `speculative` 节点不能作为实证节点的先修。
- 每个 `applied` 节点至少有一条通向 `foundation` 节点的先修路径。
- 每个已发布节点至少有一节已发布的课程。
- 世界效果引用的组件和包络都存在。
- **枢纽检查**：被超过 30 个节点直接依赖的节点给出警告，提示考虑拆分。
- **目标可行性**：每个目标都存在最小路径，路径只使用 `expert_reviewed` 节点，并落在预算之内（§9.5）。
- **路线模拟**：对目标的每条 `routes`（§7.11），用原住民研究模型做蒙特卡洛模拟，报告原住民年数的中位数和 90 分位，与锚点比较（§7.13.4）。

### 9.5 最小路径与主线脊柱

- **最小路径**：只考虑 L0–L1，求满足目标全部能力需求（含白盒要求）的最小节点集合，权重是预计分钟数。这是与或图上的最小覆盖问题：规模小时用整数规划精确求解，规模大时用启发式求解并给出下界。
- 计算结果写进 `cetus graph check` 的报告：节点数、预计时长、每项能力由哪些节点满足、替代路线的数量。
- **脊柱**（spine）：设计者指定的规范路线，用来挂剧情。玩家走替代路线同样可以达成目标；剧情在对应能力达标时触发，而不是在点亮某个特定节点时触发。

```yaml

  - id: act0
    title: { zh-CN: "降落与能源审计" }

    suggested: ["kg:eng.energy.pv-basics"]

    title: { zh-CN: "推进剂" }
    trigger: "cap(propellant.production) >= 1"
    beats: [dialog.first-hydrogen]
```

### 9.6 可见性：迷雾与全图模式

| 状态 | 规则 |
|---|---|
| 已点亮 | 已掌握（任意一层）的节点 |
| 前沿 | 当前层的先修已满足、现在就能学的节点：全部显示 |
| 轮廓 | 前沿再往外一步的节点：按相关度最多显示 k 个（默认 k = 12），其余折叠成“还有 N 个相关方向” |
| 迷雾 | 其他所有节点 |

相关度 = 与当前目标的关系（是否在最小路径或替代路线上）+ 玩家的兴趣（历史选择、搜索记录）+ 边类型的权重。之所以不用“距离 ≤ 2”这条规则，是因为复杂网络中有枢纽节点：枢纽附近距离 2 以内可能有几百个节点，冷门节点附近又可能一个都没有。

穿透迷雾的方式：
- **目标信标**：当前目标始终可见，它的能力需求以问题的形式显示（“我们需要足够的推力”），中间的路径藏在迷雾中。
- **罗盘**：鲸鱼娘建议离目标最近的前沿节点。这只是建议，玩家可以不听。
- **搜索**：搜索结果显示该节点，以及通往它的路径（P16）。
- **全图模式**：在设置中随时可以打开。已经走过的区域永久可见。
- **社交照明**：好友已点亮的节点，在你的地图上显示为微光。
- 清除迷雾是学习的自然结果（学会了，所以看见了）。**不设**随机掉落的开图道具（§3.7）。

**移动端优先**：实验台的 L0–L1 交互、判别实验台、世界视图、科技网络视图都按手机竖屏设计，桌面端自适应放大。L2–L3 的公式编辑和代码编辑以桌面为主。

### 10.2 线程模型

```
主线程 (React UI, PixiJS)
  ├─ SimWorker：当前课程或世界的 Sim 实例（WASM）
  └─ BatchWorker × k：平行星球、浏览器内的扫描（k = min(4, 核心数 - 1)）
```

- 主线程永远不直接调用 WASM 的计算接口。
- 探针数据以 `Float64Array` 作为 transferable 传输；UI 按帧节流（≤ 30 Hz）读取。
- 仿真速度与渲染帧率解耦：UI 请求“推进到时间 t”，Worker 尽快完成，然后回报结果。
- 判别实验需要同时运行真模型和误解模型两份仿真，都放在 SimWorker 中（同一种子），一次请求返回两组读数。

### 10.3 模型画布

- 基于 xyflow：存量 = 方框，流量 = 带阀门的双线箭头，辅助变量 = 圆，信息连接 = 细箭头，端口 = 边缘上的接头。
- 布局可以从 YAML 中的可选 `layout:` 字段读取；没有时自动布局。
- 洞在画布上显示为虚线框，点击后打开积木面板或公式输入框（MathLive）。
- 公式输入的实时校验：每次编辑时调用 `parseExpr`，显示量纲推导结果，例如“这个式子的单位是 W·m²，而功率应该是 W”。量纲反馈本身就是一种教学。

### 10.4 视觉风格

- M0–M3 用几何占位图形。**M4 起，鲸鱼娘必须有定稿的立绘、几套表情和关键台词**：在动机设计中，她是最重要的入口（§3.7）。其余美术仍可以用占位图形。
- M4 之后写风格指南（`docs/art/style-guide.md`）：调色板、线宽、图标网格、鲸鱼娘角色设定。AI 生成的素材必须经过人工挑选，并记录生成来源与许可。
- **鲸鱼娘形象**：方向是参考网络上流行的鲸鱼娘形象。但这类形象一般是个人画师的作品，版权属于画师；去掉商标不等于去掉版权，也去不掉与原品牌的联想。所以：
  - 使用任何现成形象之前，必须找到原作者并取得**书面授权**（最好是 CC BY、CC BY-SA 或 CC0），记录在 `assets/LICENSES.yaml` 中（P14）；
  - 拿不到授权时，委托画师或自行设计一个**原创**鲸鱼娘（“鲸鱼拟人化少女机器人”这个概念本身是通用的），轮廓和配色与现有形象明显区分，并以 CC BY-SA 授权；
  - 代理**不得**自行从网上下载角色图片入库。
- 颜色要考虑色盲安全；图表提供数据表的替代视图（无障碍）。
- 支持亮色与暗色主题，颜色用 CSS 变量定义。

## 11. 服务端与研究请求管线（M10 起）

### 11.1 服务端（保持最小）

- **内容分发**：内容仓库通过 CI 构建，`cetus bundle` 产出带内容哈希的静态文件，部署到 CDN。不需要内容服务器。
- **账号与存档**：首选托管 BaaS（Auth + Postgres + 对象存储），避免自己运维。数据表：`users`、`saves`（快照元数据 + 对象存储键）、`requests`、`votes`、`friendships`、`blueprint_shares`、`telemetry_events`。
- **遥测**：只收集学习研究和健康度评估所需的最少数据（任务完成、提示使用、用时、前后测成绩、会话时长与时段），需要玩家明确同意，并且可以导出和删除。
- **指标**（P15）：
  - 学习增益：前后测；
  - 回顾性认可：定期问一句“回头看这周，你觉得在这里花的时间值得吗”；
  - 健康度：单次会话时长分布、深夜游玩比例、“玩完后悔”的比例。

  **不以**在线时长、日活为目标。
- **A/B 测试**：只允许以上述三类指标为优化目标；正在进行的实验清单对玩家公开。

### 11.2 研究请求流程

```
玩家提交请求（自由文本）
  ─▶ 归一化（LLM）：提取主题、领域、可能的先修
  ─▶ 图谱映射：与已有节点做嵌入相似度检索，再由 LLM 判定
        ├─ 命中已有节点 ─▶ 加票
        └─ 新主题 ─▶ 提出新节点草案（含先修建议）─▶ 去重聚类
  ─▶ 优先级队列：票数 × 先修就绪度 × 对应领域审核者是否有空
  ─▶ 生成管线（§11.3）
  ─▶ 状态回传给玩家：已排队 / 研究中 / 审核中 / 已发布
```

节点发布后，世界中对应的区域或设施类型对所有玩家出现。知识图谱视图中提供一张“星球图鉴”，展示社区共同发现的全部内容。

### 11.3 生成管线（`cetus-forge`）

离线运行（开发者机器或 CI 定时任务），用一个编排脚本调用 LLM API 和 `cetus` CLI。**每一阶段的产物都落盘，可以单独重跑。**

| 阶段 | 输入 | 产出 | 自动反馈 |
|---|---|---|---|
| S1 课题简报 | 节点草案 | `brief.md`：学习目标、范式选择、范围、先修、端口、所需参数与来源清单 | 人工或 LLM 审阅 |
| S2 真模型 | 简报 + 参数库 + 作者指南 + 范例 | `module.yaml` + `README.md` | `cetus check --json` 循环自修，最多 N 轮 |
| S3 行为测试 | 模块 + 来源 | `tests/behavior.yaml` | `cetus test` |
| S4 课程设计 | 模块 + 目标 | `lesson.yaml`（洞、仪器、任务、误解模型、教学任务） | `cetus verify --level V4` |
| S5 叙事与文本 | 课程 | 对话、i18n 文本（含原住民对误解的说法、请教事件的开场、指向本节点的小故事） | 长度与风格检查 |
| S6 全量验收 | 全部 | 验收报告 | `cetus verify --level V5` |
| S7 预审 | 全部 + 报告 | LLM 预审报告（换一个模型） | — |
| S8 提交 | 全部 | 内容仓库中的 PR | 人工 / 专家审核 → 合并 → 发布 |

规则：
- 参数**只能**引用参数库中已有的条目。需要新参数时，生成“参数请求”，由专家补充来源，**不允许 LLM 自己编写文献引用**。
- 生成者和预审者使用不同的模型。
- 连续 N 轮无法通过 `check` 的任务自动放弃，并记录失败模式，用于改进作者指南。

## 12. 里程碑与实现路径

### 12.0 说明

- 估时按“1 名全职开发者 + AI 编码代理”估算，只是粗略范围。实际进度取决于投入时间和对 Rust 的熟悉程度。每个里程碑结束时回顾，并修正后续估时。
- 每个里程碑都有**退出标准**。没有全部满足，就不进入下一个里程碑。
- **M4 结束时有一个是否继续的决策点**：先验证“玩家真的学会了”，再做平台化。
- M5 之后，专家可以并行贡献内容；M6–M9 的顺序可以根据哪类专家先到位来调整（例如先有物理专家就先做 PDE）。
- 建议在 M3–M4 期间先请 1–2 位专家做顾问，参与首批课程的设计评审，不必等到 M5。
- **内容轨（与 M0–M4 并行，现在就可以开始）**：用 `skills/cetus-knowledge-network` 让调研能力强的模型先搭起科技网络的骨架；`skills/research-misconceptions` 可以并行，为第一阶段节点整理误解目录。检查点：M3 结束前，完成第一阶段最小路径的骨架（节点、按层先修、能力映射、预算估算），供 M4 选课和校准；之后按领域逐步扩展，供专家审核和填充。

## 13. 工程规范

### 13.1 代码
- Rust：edition 2024；`#![forbid(unsafe_code)]`（WASM 绑定层除外，需要时单独说明）；公共 API 写文档注释；错误类型用 `thiserror`。
- TS：`strict: true`；不使用 `any`（确实需要时加注释说明）；组件和逻辑分离。
- 仿真相关代码中**没有**无注释的魔法数字；常数要么来自模型文件，要么在 `cetus-math` 中命名。

### 13.2 测试
- 每个 crate 都有单元测试；`cetus-units`、`cetus-expr`、快照有属性测试。
- 样板模型和已发布模块有黄金轨迹回归测试。黄金轨迹的更新必须在 PR 中说明理由。
- 跨目标确定性测试覆盖所有样板模型。
- 前端：关键交互用 Playwright 做端到端测试（加载课程、补全洞、通过检查、完成一次判别实验）。

### 13.3 提交与评审
- 约定式提交（`feat(expr): ...`、`fix(sd): ...`）。
- 每个 PR：一个主题、附测试、关联里程碑任务；涉及 schema 或公共 API 的，同步修改文档。
- 代理提交的 PR 在描述中列出：做了什么、满足哪条退出标准、有哪些已知限制。

### 13.4 ADR
- 格式：背景、选项、决定、后果。编号递增，不删除，只能“被取代”。
- 需要 ADR 的情况：引入新依赖、改变 schema 主版本、违背或修改 §2 的任何一条、改变确定性策略。

### 13.5 诊断与文档
- 新增诊断码时，必须同时新增 `docs/errors/<code>.md`。
- 每个 schema 区块在 `docs/authoring/` 中有一页说明，并附最小示例。

## 15. 术语表

| 术语 | 含义 |
|---|---|
| 模块（module） | 一份声明式仿真模型文件（`module.yaml`），描述一个可运行的系统 |
| 课程（lesson） | 基于模块的引导探究活动，含仪器、洞、任务、检查器、误解模型 |
| 真模型（truth） | 课程背后对玩家隐藏的参考模型，用于生成观测和判定 |
| 洞（hole） | 玩家模型中被挖掉、需要玩家补全的方程、参数、连接、规则或代码 |
| 误解模型（misconception） | 体现常见错误理解的模型补丁，必须被检查器拒绝 |
| 变异杀伤率 | 自动生成的错误变体被检查器拒绝的比例，用来衡量课程的区分力 |
| 教学即复习 | 把学会的东西教给子代理或原住民，既是玩法，也是间隔复习的形式（§6.8） |
| 判别实验 | 一组实验设置，在其中真模型与某个误解模型的观测差异明显超出仪器噪声；教原住民的核心任务（§6.8.3） |
| 请教事件 | 新一代原住民或来访者带着误解来请教，由 FSRS 调度，是原住民线的复习形式（§6.8.4） |
| 新情况 | 子代理按玩家教的模型工作时遇到的条件变化，以运维事件出现，练的是迁移（§6.8.4） |
| 原住民时钟 | 世界日历按活跃在线时间推进，约 7.5 分钟 = 1 个季度（§7.12） |
| 时间额度 | 原住民时钟每周可推进的原住民年数；用完只停原住民时钟，不限制学习（§7.12.3） |
| 实验沙盒 | 课程中的小时级仿真，模拟典型的一天，不推进世界日历（§7.12.1） |
| 研究进度 / 突破 | 原住民确定性累积的研究存量；满了就发生一次突破，方向加权随机（§7.13.2） |
| 原住民路线 | 部分阶段能力由原住民发展提供的混合路线；驾驶员始终由玩家提供（§7.13） |
| provenance（来源） | 目标中一项能力允许的来源：`player`、`native_developed`，或不限（§7.11） |
| 小故事 / 编年史 | 季度报告中指向未学知识的原住民故事（可带猜想），全部收入村落编年史（§7.14） |
| 范式（paradigm） | 一类仿真形式：SD、ABM、PDE、刚体、算法轨迹等 |
| 子系统（subsystem） | 范式编译后的可执行单元，由调度器推进 |
| 宏步（macro step） | 调度器在子系统之间交换数据的固定时间步长 |
| 分析（analysis） | 对模型要做的计算：瞬态、扫描、稳态、优化、拟合、线性化等（K3） |
| 数据集（dataset） | 所有仪器和分析的统一输出格式：带单位、带维度的多列数据（K4） |
| 核心抽象（K1–K14） | 所有范式共用、在 M1 就要定好接口的底层设计（§5.6.3） |
| 波次（wave） | M5 之后由专家驱动的范式扩展批次（§12.2） |
| PyWorker | 运行 Pyodide 和学习者 Python 代码的专用 Web Worker |
| 表示层（L0–L3） | 同一个真模型的四种学习方式：直觉、因果、定量、推导或代码（§3.6） |
| 能力（capability） | 世界可测量的本领，分若干等级；节点提供能力，目标需要能力（§7.11、§9.4） |
| 目标（goal） | 按能力需求定义的阶段目标（§7.11） |
| 白盒要求 | 某项能力的 `provenance` 只允许 `player`，即必须由玩家自己掌握的节点提供（第一阶段只有驾驶员如此） |

| 端口（port） | 模块对外暴露的连接点 |

| FSRS | Free Spaced Repetition Scheduler，一种开源的间隔复习调度算法 |
