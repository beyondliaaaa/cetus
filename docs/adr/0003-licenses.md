# ADR-0003：许可证

- 状态：已接受（2026-10-23，M0；对应指南 Q2）
- 相关：§1.2、§14.1 Q2、P14、§9.1

## 背景

项目是非营利导向的公益教育项目（§1.2），希望尽可能多的人能使用、修改、再分发，
同时希望社区对内容的改进也能回馈回来。引擎与内容的使用场景不同：

- 引擎：希望被尽可能广泛地集成（包括商业公司的内部培训、学校自建平台）；
- 内容：希望保持开放，且修改后的内容也必须开放（避免出现「拿走向日葵然后锁起来」
  的版本）。

## 决定

| 部分 | 许可证 |
|---|---|
| 引擎代码（本仓库 `crates/`、`packages/`、`apps/`、`scripts/`） | `MIT OR Apache-2.0` 双许可 |
| 内容（未来的 `cetus-content` 仓库：模块、课程、文本、世界定义、数据集） | `CC BY-SA 4.0` |
| 美术与音频素材 | 逐个记录在 `assets/LICENSES.yaml`，优先 CC0 / CC BY / CC BY-SA（P14） |

## 理由

- **MIT OR Apache-2.0**：Rust 生态的事实标准。MIT 简单，Apache-2.0 含专利授权与
  商标条款；双许可让使用方按需选择。
- **CC BY-SA 4.0**：内容需要署名（学术来源与作者）并以相同方式共享。与「知识应该
  自由传播、但改进也应回流」的初心一致。
- **素材逐个记录**：P14 要求任何素材入库时在 `assets/LICENSES.yaml` 记录作者、来源、
  许可证；没有记录 CI 拒绝合并。角色形象（Q10）在取得书面授权前**不得**入库。

## 后果

- 每个源文件不需要单独写 license header；仓库根部的 `LICENSE-MIT`、
  `LICENSE-APACHE` 与 `README.md` 的说明即为全部。
- 内容仓库需要单独的 `LICENSE`（CC BY-SA 4.0 全文）与贡献者指南。
- `assets/LICENSES.yaml` 的 CI 检查在 M0 建立骨架（当前为空列表），从 M4 起强制。
- 如果将来引入第三方数据集（§6.3），数据集许可证必须与 CC BY-SA 4.0 兼容，并在
  `datasets/<id>/source.yaml` 中记录；不兼容的数据集只能用于「引用数值」而不能
  打包分发。
