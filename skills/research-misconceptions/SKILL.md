# 误解与错误理论调研（鲸鱼娘历险记 / Cetus）

> **skill 版本**：v0.1（2026-10-23）· **对应指南版本**：v0.5.2
> 指南版本高于上面的数字时，先读指南 §6.1、§6.8、§7.14 的最新版本；两者冲突时以指南为准，并在报告中指出。

## 0. 你的任务与产出

为科技网络中的节点，整理一份**有出处的误解目录**。一条好的误解条目会被三个下游使用：

| 下游 | 怎么用 | 指南章节 |
|---|---|---|
| 课程的误解模型 | 写成模型补丁，检查器必须能拒绝它（V4） | §6.1、§8.5 |
| 教原住民的判别实验 | 原住民持有这个误解，玩家设计实验让他们亲眼看到 | §6.8 |
| 小故事里原住民的猜想 | “错但不离谱”的猜想；偶尔原住民是对的 | §7.14 |

**产出**（放在内容仓库 `cetus-content/misconceptions/` 下）：
1. `misconceptions/<domain>/<node-short-name>.yaml`：每个节点一个文件，里面是条目列表（格式见 §3）。
2. `misconceptions/reports/<日期>-<批次>.md`：每批工作的调研报告（模板见 §7）。

**不属于你的任务**：写课程 YAML、写模型补丁的正式代码、写台词和小故事正文。你只给出**想法**（补丁的思路、判别观测的思路、原住民说法的方向），由其他 skill 落地。

## 1. 背景（读不到指南时的最小上下文）

- 这是一个教育游戏。玩家通过有引导的探究重建科学知识：用仪器观测“星球实测数据”，补全模型，预测，对照。每节课背后有一个隐藏的**真模型**。
- **误解模型**是对真模型的一个补丁，体现一种常见的错误理解。例如“认为光伏功率与辐照度的平方成正比”，补丁就是把 `η·A·G` 改成 `η·A·G²/G₀`。课程必须能用观测数据把它和真模型区分开。
- 表示层：L0 直接操作，L1 只画因果箭头（增加 / 减少），L2 写带单位的公式，L3 推导或写代码。误解也分层：L1 的误解通常是因果方向错了；L2 的误解通常是函数形式、漏项或量纲错了。
- **原住民**：星球上处于语言初级阶段的智慧族群，与鲸鱼娘合作互惠。他们会对看到的现象提出猜想，这些猜想“错但不离谱”，最好取材于人类历史上真实出现过的错误理论。偶尔原住民是对的，玩家第一反应的“科学解释”反而错了。
- 节点 ID 形如 `kg:phys.thermo.heat-capacity`，由 `cetus-knowledge-network` skill 维护。

## 2. 硬规则

- **M1 不编造**：每条误解都要有你**实际读过**的出处（论文、综述、概念量表的研究、教材中关于常见错误的章节、科学史著作）。找不到出处但你认为合理的，`kind` 写 `hypothesized`，并在 `evidence` 中写“无文献，推测理由：……”。不得编造论文标题、作者、年份、网址或流行率数字。
- **M2 区分来源类型**：`research_documented`（教育研究中记录的学习者误解）、`exam_item`（考题或概念量表中稳定出现的错误做法）、`historical_theory`（科学史上的错误理论）、`folk_belief`（民间说法）、`hypothesized`（推测）。不要把推测写成有文献支持。
- **M2a 考题来源**：`exam_item` 必须写明题目出处（考试名称、年份、题号，或研究中的题目编号）；只有当这个错法能稳定地写成模型补丁时才收录。
- **M3 改写，不抄录**：用自己的话概括出处中的内容。引用原文时每条不超过一句短语，并注明出处。
- **M4 不贴文化标签**：不要把错误理论归属到某个现实中的民族、地区或宗教，只写“历史上曾有人认为”以及具体的学者或时期。原住民是虚构的族群，他们的猜想不影射任何现实文化。
- **M5 “原住民是对的”要有硬证据**：民间做法后来被证实有效的例子，必须有可靠的科学出处，并写清楚它在什么条件下有效、在什么条件下无效。拿不准就不收。
- **M6 尊重**：条目中的表述要认真对待持有误解的人，说明它为什么在有限证据下是合理的。不写嘲讽。
- **M7 不写教学内容**：不写课程、题目、台词正文。

## 3. 条目格式（`cetus.misconception/0.1`）

```yaml
schema: cetus.misconception/0.1
id: "mc:phys.thermo.caloric"                       # mc:<领域>.<子领域>.<短名>，与节点 ID 规则相同
nodes: ["kg:phys.thermo.heat-vs-temperature", "kg:phys.thermo.heat-capacity"]
layer: L1                                          # 这个误解主要出现在哪一层：L0 | L1 | L2 | L3
kind: historical_theory                            # research_documented | exam_item | historical_theory | folk_belief | hypothesized
statement:                                         # 持有者会怎么说（第一人称或转述，口语化）
  zh-CN: "热是一种看不见的流体，从热的东西流进冷的东西；东西装得下的‘热’越多，就越难变热。"
correct_view:
  zh-CN: "热量是能量转移的方式，不是物质；但在没有做功、没有相变的情况下，‘热量守恒地流动’这个图像能做出正确的预测。"
why_plausible:
  zh-CN: "在量热实验中，热量确实表现得像守恒的流体；这个理论成功解释了热平衡和比热。它在摩擦生热这类现象上失效。"
evidence:
  - source: "<你实际读过的科学史著作或论文，作者、标题、年份>"
    summary: "<用自己的话概括出处的相关内容>"
  - source: "<教育研究中关于学生持有类似观念的文献>"
    summary: "……"
prevalence: "TODO(expert)"                         # 只有出处给出时才写具体数字，并注明人群
regime:                                            # 在什么条件下，这个误解与真模型的预测一致，在什么条件下分歧
  agrees_when: { zh-CN: "只有热传导、没有做功和相变" }
  diverges_when: { zh-CN: "摩擦、压缩气体、搅拌液体：‘热’凭空增加" }
patch_idea:                                        # 写成模型补丁的思路（不是正式代码）
  patchable: partial                               # yes | partial | no
  sketch: { zh-CN: "把‘热量’建成一个只能转移、不能被做功产生的守恒存量；在有搅拌功输入的模型中，补丁去掉功→内能的流" }
  why_not: ""                                      # patchable 为 no 时写原因
discriminating_observation:                        # 让人亲眼看到差异的观测思路
  zh-CN: "在绝热容器里持续搅拌水，测量温度：真模型预测温度持续上升，误解模型预测温度不变"
story_use:
  suitable: true
  natives_phrasing_direction: { zh-CN: "原住民说‘热是太阳装进石头里的东西，用完就没了’" }   # 方向，不是正文
  natives_right: false
confidence: medium                                 # high | medium | low；low 必须写原因
notes: ""
```

**“原住民是对的”的条目**（`natives_right: true`）额外要求：

```yaml
kind: folk_belief
statement: { zh-CN: "<民间做法或说法>" }
correct_view: { zh-CN: "<为什么它在某些条件下是对的，以及它的边界>" }
tempting_wrong_explanation:                        # 玩家第一反应可能给出的“科学解释”，以及它错在哪里
  zh-CN: "……"
evidence:
  - source: "<可靠的科学出处>"
    summary: "……"
```

## 4. 什么是好的误解条目

**收录**：
- 很多人真的会这样想（有研究记录，或在科学史上被认真持有过）；
- 内部自洽，能做出预测；
- 在某个可观测的条件范围内，**预测与真模型不同**。这是它能变成判别实验的前提；
- 最好在另一些条件下预测与真模型**一致**。这正是它“错但不离谱”、难以被随手推翻的原因，也让判别实验有设计空间。

**不收录**：
- 单纯的口误、计算失误、记错公式；
- 纯粹的术语混淆（例如只是把“功率”说成“能量”，而理解本身没错）；
- 无法与任何观测联系起来的说法。

**每个节点的目标数量**：2–5 条，其中至少 1 条是 L1 层（因果方向错了）的误解，因为主线只用 L0–L1。每 5–10 条中，尽量有 1 条 `natives_right: true` 的候选（全局比例目标约十分之一到五分之一，由内容设计最终决定）。

## 5. 补丁思路的常见类型

写 `patch_idea` 时，以下类型最容易落地为模型补丁：

| 类型 | 例子 | 补丁形式 |
|---|---|---|
| 因果方向错 | 以为负荷越大电池充得越快 | L1：翻转一条因果箭头；L2：改变某项的符号 |
| 函数形式错 | 功率与光照的平方成正比 | 替换一个表达式 |
| 漏掉一项 | 忽略昼夜，把辐照度当常数 | 用平均值替换随时间变化的项 |
| 存量与流量混淆 | 把“充电速度”当成“电量” | 把流量直接当存量使用，或去掉积分 |
| 守恒量搞错 | 热质说：热只能转移不能产生 | 去掉一条产生或转化的流 |
| 线性外推 | 以为种群会一直按同样速度增长 | 去掉承载力项 |
| 忽略延迟 | 以为调节水龙头后水位立刻稳定 | 去掉延迟或把延迟时间设为 0 |
| 比例与绝对混淆 | 以为火箭加倍燃料，速度增量加倍 | 用线性关系替换对数关系 |

纯本体论的误解（例如“热是一种物质”）往往仍有可计算的推论（例如“热守恒”），尽量找出这个推论。实在找不到，`patchable: no` 并写明原因，它仍可以作为小故事的素材。

## 6. 工作流程

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| A 选批次 | 从第一阶段最小路径的节点开始（由 `cetus-knowledge-network` 产出），一批 5–10 个节点 | 批次清单写进报告 |
| B 读节点 | 读每个节点的 `understanding`、各层说明和 `research.notes`（里面可能已有调研时顺手记下的线索） | — |
| C 查文献 | 学科教育研究（概念量表及其相关研究、误解综述）、科学史、教材中关于常见错误的部分；民间做法只查可靠的科学出处 | 每条条目至少 1 个实际读过的出处，或标为 `hypothesized` |
| D 写条目 | 按 §3 格式；先写 `regime`，再写 `patch_idea` 和 `discriminating_observation` | 每个节点 2–5 条，至少 1 条 L1 |
| E 自检 | §8 清单 | 全部通过或在报告中说明例外 |
| F 报告 | §7 模板 | — |

第一批完成后先停下，等人类审阅格式和质量，再继续。

```markdown

## 需要专家确认的问题
1. ……（指出条目 ID）

## 实际查阅过的资料
- ……
```

## 8. 自检清单

- [ ] 每条条目都有实际读过的出处，或已标为 `hypothesized` 并写明推测理由（M1、M2）。
- [ ] `exam_item` 条目写明了题目出处，且错法能稳定地写成模型补丁（M2a）。
- [ ] 没有编造的论文、作者、年份、网址、流行率（M1）。
- [ ] 没有大段抄录原文（M3）。
- [ ] 没有把错误理论归属到现实中的民族、地区或宗教（M4）。
- [ ] `natives_right: true` 的条目都有可靠出处，并写清了适用边界（M5）。
- [ ] 每个节点至少 1 条 L1 层误解。
- [ ] 每条条目都写了 `regime.diverges_when`；写不出的不收录。
- [ ] `patchable: no` 的条目都写了原因。
- [ ] ID 符合规则，没有重复。

## 9. 常见错误

- 把“学生常犯的计算错误”当成误解收录。误解是一种连贯的错误理解，不是一次失误。
- 只写误解是什么，不写它在什么条件下与真相一致。没有这一项，下游无法设计判别实验。
- 为了凑数，把推测写成有文献支持。
- 把历史上的错误理论写成笑话，或写成“古人很蠢”。它们大多是当时证据下最好的解释。
- 原住民的说法直接套用现实中某个文化的信仰或习俗。
- “原住民是对的”的例子缺少边界，导致玩家学到“土办法总是对的”。
